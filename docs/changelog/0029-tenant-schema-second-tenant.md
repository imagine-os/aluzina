# 0029 - `tenant.schema.json`, schema + actions checks in `tenant-validate`, second-tenant recipe, host tenant index shape

## Schema: `tenant.schema.json` (repo root)

JSON Schema draft 2020-12 for manifest v1, describing exactly what `tenant.json` contains today: the eighteen required top-level keys (the validator's `REQUIRED` list), `manifestVersion` as `const 1`, `identity`, `brand`, `surfaces`, `hubModules[]` (`shell` enum `desktop | phone | bare`), `subProjects[]` (`kind` enum `app | static | external | data | pipeline | docs | platform-candidate`, `status` enum `done | doing | next | backlog | live | linked`), `data` (`baseRow` items enumerated, D-091), `contentMounts[]`, `namespace` (derived-value patterns for `storagePrefix`, `channels`, `global`), `routing` (`strategy` and `supports` enums `path | subdomain`), `deploy`, `docs.counters` (the four counters required, integers), `actions` (`global` pattern `window.__<id>.actions`), `hostRequirements[]` (`HR-nn`). Three `$defs` (`repoPath`, `pageCode`, `hrId`) keep the patterns in one place.

Every `description` starts with a tag so a second tenant knows what to fill and what to copy: `[required, tenant-specific]`, `[required, platform-fixed]`, `[required, derived]` (a function of `id`), `[optional]`. Objects are open unless the spec closes the set: only `routing` (D-097: the host reads exactly three fields), `namespace.storageKeys` (the browser has exactly `localStorage` and `sessionStorage`) and `deploy.docsAlias` (`alias` + `path`) carry `additionalProperties: false`. `name` allows any language key as a string with `en` required; `surfaces.codePrefixes` allows any uppercase prefix. Optional fields present in aluzina's manifest (`generatedFrom`, `spec`, `legalName`, `publicSite`, `contactChannels`, `brand.documents / renders / sourceKit / brief`, `data.domainDir / docsInputs / idScheme / plannedProvider`, `namespace.htmlAttributes / demoEmailDomain / literalAllowlist`, `deploy.url / staticCopies / deployTimeArtifacts / envVars / buildDefines`, the non-core `docs.*` paths, `actions.browser / exportFormat / mcpServer`, `hubModules[].platformCandidate / note`) are all declared, so nothing in today's file is an "unknown key". A `stack` field on `subProjects[]` is declared for a `kind: app` whose stack is not the hub (the recipe uses it).

## Validator additions (`scripts/tenant-validate.mjs`)

- **(j) Structural check.** Before the nine existing checks, the manifest is walked against the schema with a hand-written, dependency-free walker for the subset used: `type` (string or array, `integer` distinguished), `const`, `enum`, `pattern`, `required`, `properties`, `additionalProperties` (`false` or a schema), `items`, and `$ref` to a local `#/$defs/<name>`. Any other keyword in the schema is itself reported as a failure, so the schema cannot drift outside what the walker enforces. The schema is read from `tenant.schema.json` next to the manifest when the tenant ships one, otherwise from this repo's copy. Failures read `schema: tenant.subProjects[1].kind is "widget", expected one of "app" | ...`. Aluzina's manifest yields 800 checked nodes, zero failures.
- **(k) Actions recount.** Every `hubModules[].path/specs.ts` is scanned for `id: '<module>.<verb>'` literals matching `actions.idPattern`; `actions.declared` must equal the count and `actions.distinct` the number of distinct ids. Result on `main`: 430 / 409, the values already in the manifest (unchanged since 0028). `docs/tenant/manifest.md`'s note that tp-11 would own this recount is updated: it is in the validator now.
- **`--manifest <path>`.** The manifest's directory becomes the repo root every relative path resolves against, so a second tenant's manifest validates in place from this checkout: `node scripts/tenant-validate.mjs --manifest ../between-gigs/tenant.json`. Without a `package.json` next to the manifest the run stops with one line (`--manifest must point at a tenant repo's root manifest`); `--manifest` without a path exits 2. The hub-specific checks (modules folder, `PageSpec.ts`, `EntityMap`, seed folder, docs folders, namespace scan roots) now report a missing folder as a failure line instead of throwing, so a non-hub-shaped repo gets a readable list.
