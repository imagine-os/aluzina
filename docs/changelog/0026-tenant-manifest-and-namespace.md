### tp-04: `tenant_id` + `version` on every row

1. `data/schema/base.ts`: `BaseRow` gains `tenant_id: string` and `version: number` (documented). `NewRow` omits `keyof BaseRow`, so callers never supply them; the `DataProvider` interface is unchanged.
2. **Stamped centrally**: `seed/index.ts` `ctx.add` stamps `tenant_id: TENANT.id, version: 1` on every seeded row (no seed module edited for it); `MockProvider.create` stamps the same; `update` sets `version: before.version + 1` and keeps `tenant_id`; the `activity` rows the provider writes carry them too. Last-write-wins + `onConflict` behaviour is unchanged. `archiveRows.ts` (lazy chunk rows) and `work/sample.ts` (component examples) stamp them by hand because they never pass through the provider; `archiveFiles.saveFilePatch` strips them from the draft before `create` like the other base fields.
3. **`SEED_VERSION` 12 -> 13**: every browser re-seeds once on first load (saved edits in `aluzina.data` are dropped, as on every seed bump; Work views, sets, language and theme are separate keys and stay).
