## 6. Data layer

- **Interface:** `apps/hub/src/data/provider.ts` `DataProvider { name; list(entity, {where, orderBy, dir, limit}); get; create(entity, data, id?); update(entity, id, patch, {basedOn?}); remove; subscribe(entity|'*', cb) ; onConflict(cb); setActor(userId); reset() }`, all async so a backend can replace it silently. Consumed via `data/DataContext.tsx` hooks `useTable / useRow / useData`.
- **Base row:** `data/schema/base.ts` `{ id, created_at, updated_at, updated_by? }` (P-14). Ids are string slugs (`prj-*`, `cl-*`, `u-*`, `sp-*`) in seeds; `newId(prefix)` = `${prefix}-${Date.now().toString(36)}${counter}` for new rows. No `version` column yet (planned, D-024/step 8).
- **Schema:** 37 entities in `data/schema/index.ts` `EntityMap`: projects, sections, tasks, comments, activity, meetings, suppliers, quotes, deliveries, payments, documents, references, materials, schedules, renderPacks, consistencyChecks, competitions, presentations, brandAssets, revisions, alerts, spaces, posts, filings, relations, tags, clients, deliverables, tools, leads, engagements, revisionItems, changeOrders, purchases, siteReports, messages, assets. `relations` is the generic cross-entity link table (kinds `references, applies-to, part-of, replaces, depends-on, belongs-to, produced-by, for-client, owned-by, depicts`; targets may be entity names or registries `roles/users/services`).
- **Implementation:** `data/MockProvider.ts` only (`name: 'mock'`): in-memory tables persisted whole to `localStorage['aluzina.data']` as `{ seedVersion, tables }`; seeds re-run when `SEED_VERSION` (12) changes; `activity` rows appended per changed field (cap 500); optimistic concurrency = `basedOn` compared with `updated_at`, last-write-wins + `onConflict` toast (D-024).
- **Seeds:** `data/seed/index.ts` globs `./*.ts` (16 modules with `order` + `seed(ctx)`), `SEED_AT` fixed timestamp; seeds derive rows from `@docs` JSON (brand assets, archive inventory, company docs, collections) and from Asana exports.
- **Realtime/multiplayer stubs:** `BroadcastChannel('aluzina-data')` carries every write (with changed rows) to other tabs, `storage` event fallback (D-023); `presence/PresenceProvider.tsx` heartbeats `{tabId,userId,route,at}` on `BroadcastChannel('aluzina-presence')` every 5 s, expire 15 s, `usePresence()` -> `PresenceBar`. Docs say Supabase Realtime/Presence "replaces the channels behind the same seams"; no Supabase code exists (only 15 comment/doc mentions). No offline queue, no file storage seam (`put(file) -> url` is backlog; archive renders are committed static files).
- **Lazy data outside the store:** `data/archiveFiles.ts` builds `assets` rows in memory from lazy `docs/archive/projects/<slug>/index.json` chunks, overlaying stored "patch rows" with the same id (D-071); `domain/collections.ts` lazy-globs collection indexes, never seeded.
- **Per-user browser state:** `aluzina.views.<userId>` saved Work views (D-025), `aluzina.archive.set`, `aluzina.graphView`, intake draft in sessionStorage.
- **Storage summary:** localStorage/sessionStorage/BroadcastChannel only. No backend, no HTTP API, no auth (identity mocked, permission guards real, P-12).

## 9. Assessment: tenant content vs platform, and obstacles

**Tenant-owned content (Aluzina-specific):**
- `docs/**` almost entirely (knowledge base, playbook, brand kit, archive indexes, prompts/changelogs/decisions history, screenshots, source captures).
- `apps/hub/public/{archive,brand}` (122 MB renders, brand PDFs/SVGs), `src/brand/paths.ts`, brand hexes in `tokens.ts`, `styles/textures.css`, `index.html` favicon/title/fonts.
- `src/domain/*` (playbook, templates, archive/collections vocab), `src/data/seed/**` (incl. Asana seeds), `src/data/schema/*` field-level choices (COP, 15 pipeline statuses).
- `src/auth/{roles,permissions,demoUsers}.ts`, `src/app/navGroups.ts`, module `strings.ts`, hub card lists in `modules/hub/HubPage.tsx`, module page content of founder/ops/studio/brand/client/public/manual/archive/sets/work/spaces.
- `apps/business-os/` (the client's prototype) and its media.
- Root README, `.github/workflows/pages.yml` target, `scripts/import-asana.mjs`, `scripts/archive/*` rule tables.

**Platform/tooling a multitenant host should own:**
- Module contract + registry (`app/registry.ts`, `specs/PageSpec.ts`, `RouteDef`, `defineSpec`, `specCompleteness`), shells (`app/shells.tsx`), `manifest.ts` (`window.__aluzina` -> should become `window.__<host>` or tenant-keyed).
- Actions bus (`src/actions/*`), `DevTools`, `Placeholder`, dev-mode/role-switcher mechanics (`SessionProvider`, `RequireRole`, `hasPermission`), `?as=` contract.
- i18n runtime (`I18nProvider`, `types.ts`), theme runtime (`ThemeProvider`, `gen-tokens.mjs`, token *shape*), component library (50 components + `library.ts`/`meta.ts`), `DataProvider` interface + `MockProvider` + `DataContext`, `PresenceProvider`, `work/` model, `plan/` reader, tools/qa/dev/docs/design modules (generic builder pages), `scripts/{thumbnails,screenshots,copy-static}.mjs`, docs conventions (numbering, templates, `surfaces.md` shape, knowledge-entry header).

**Biggest obstacles to lifting this in as one tenant (top 9):**
1. **Tenant data is compiled into the bundle via `@docs`:** the app imports `docs/plan/plan.json`, `docs/archive/**/*.json`, `docs/brand/*/index.json` and every `docs/**/*.md` (in-app docs viewer, lazy). A host must either give each tenant its own `docs/` mount + alias or move these to fetched data. Build fails without them.
2. **Single hardcoded namespace everywhere:** `aluzina.*` localStorage/sessionStorage keys, `aluzina-data`/`aluzina-presence` BroadcastChannels, `window.__aluzina`, `@aluzina/hub`, `data-*` attributes; two tenants on one origin would collide in storage and presence.
3. **No backend, no auth, no tenant id in the data model:** `MockProvider` persists one blob in localStorage; rows have `id/created_at/updated_at` but no `tenant_id`/`org_id`, no `version`; permissions and roles are compile-time constants for Aluzina's org chart (`founder: ['*']`). A host needs a real `DataProvider` (Supabase planned but zero code) and tenant scoping added to every entity and seed.
4. **Fixed surface/role/page-code vocabulary in code:** `Surface` union, `CODE_RE` prefixes `[PCAOSGMDWK]`, `NAV_GROUPS`, `ROLE_META`, hub card lists, `thumbnails.mjs` card list, `screenshots.mjs` role map — all constants that a second tenant with different portals would have to fork.
5. **Design tokens are the tenant's brand:** `tokens.ts` mixes the token *schema* (platform) with Aluzina's values (silver/gold metal ramps, pastels, DIN Round Pro, textures, `BrandMark` SVG paths); the generated `tokens.css` is committed. Needs a values/schema split and per-tenant theme loading.
6. **Repo weight and committed binaries:** 377 MB tree / 286 MB `.git`; 122 MB archive renders + 141 MB prototype + 69 MB screenshots are committed and copied into `dist` (278 MB). Redaction rules (D-059) exist because the Pages site is public; a private tenant host changes that calculus but the assets still need object storage, not git.
7. **GitHub Pages / relative-base assumptions:** `base: './'`, HashRouter, `dist/` at repo root, `.nojekyll`, `copy-static.mjs` and forwarder HTML for the prototype, thumbnails generated at deploy on `127.0.0.1:4180`; Pages workflow uses `enablement: true`. Fine for one tenant, awkward for a host with path- or subdomain-based tenancy.
8. **The Business OS prototype is a runtime-Babel static bundle** with space-containing filenames, own inline i18n, no manifest/actions integration; it can only be iframed/linked, not composed.
9. **Process/docs conventions are repo-local and agent-driven:** append-only numbered prompts/changelogs/decisions, `_pending` merges, "commit straight to main, no PRs", model attribution per changelog, `surfaces.md` updated every pass; 88 commits all by "Claude" in 2 days. A multitenant host needs these as per-tenant folders (or a shared counter policy) and its own CI gates (there is no lint or test suite to inherit — only `tsc` inside the build).
10. (Bonus) **No quality automation beyond tsc:** no ESLint, no unit/e2e tests, QA is Markdown matrices + Playwright screenshots; the 44 px / 7-width / EN-ES bar is enforced by convention (`checkedAt`) rather than CI.
