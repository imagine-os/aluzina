## Purpose

Every project the studio has ever had, in one browser. Justin's ask in #past-projects was to stop treating the Dropbox archive as a different world from live work: "separate past and complete stuff from in-progress and new prospects, but sometimes we want to see everything", and "review past stuff when building a portfolio, or sets of related examples to show specific clients". So the page lists **all** projects — the `prj-ar-*` rows seeded from the Dropbox inventory, the `prj-pf-*` portfolio rows and the live hub projects — with lifecycle tiles that narrow to prospects, work in progress or past work, and an "All" tile that is the default. Each project reads as itself at a glance (cover thumbnail or a mosaic of its file-type icons, client, year, status, tags, file count), and the portfolio set lets a person tick the projects they want to show one client and copy them out as a list.

4. **Cards**: a responsive grid (1 column at 360/390, 2 at 768, 3 at 1280, 4+ from 1920) of `Card`s. In portfolio-set mode a `Checkbox` row sits under the link (a second tab stop, never inside the link).
5. **Table**: `DataTable` with project, client, year, type, status, lifecycle and file count; rows activate to S-13.
6. `EmptyState` when nothing matches, with a "Clear filters" button.
7. Sticky portfolio-set bar (only in set mode with a selection): "N projects selected", **Open example page** (P-06 in a new tab), **Export PDF** (the same link with `print=1`), **Save set to Spaces** (`spaces.write` only), **Open the saved set** once a set has been saved, **Copy list**, **Clear**. ## Data

Read only. `projects` (all rows; `tags`, `year`, `fileCount`, `coverUrl`, `fileTypes`, `archiveSlug`, `sourceFolderUrl`, `pipelineStatus`). Since ar-19 no file rows are seeded: counts, covers and the mosaic types are columns of the project row, written by the seed from `docs/archive/index.json`. `assets` (`kind: 'file'`) and `relations` (`kind: 'belongs-to'`) are read only for the **curated** files — the stored rows S-13 creates through `saveFilePatch` (`apps/hub/src/data/archiveFiles.ts`) when someone tags or moves a file — which give the "N tagged" meta and extend the Tag filter. `clients`, `spaces`, `filings` and `posts` are declared in the spec because S-13 shares the module's data contract. S-12 itself writes nothing but `localStorage['aluzina.archive.set']`; the tag, stage and cover writes live on S-13 and reach this page through the provider's `subscribe` events.

## Logic

- **Lifecycle** is derived, never stored: `lifecycleOf(project.pipelineStatus)` from `domain/archive.ts`. Lead statuses are prospects, `contracted`..`punch-list` is in progress, `delivered`/`closed`/`follow-up` is past. That is why a live project and a 2019 Dropbox folder can sit in the same list without a second status vocabulary.
- **Filters are the query string** (`?life=&year=&type=&tag=&q=&sort=&view=&set=`), written with `replace: true`. A view is therefore a link, the back button works, and `archive.filterLifecycle {life: 'past'}` through the actions bus produces exactly the URL a person would have produced by clicking (verified: `{ ok: true, result: 'past' }`, URL `#/studio/archive?life=past`).
- **Covers**: `project.coverUrl` (the served thumbnail path, set together with `coverAssetId` by the seed from the inventory's `cover` and by S-13 "Set as cover"). With no cover, a 2x2 mosaic of `FileIcon`s for `project.fileTypes` (the folder's four most common file types, from the inventory's `extensions`); with no files at all, a single folder icon. A project is never shown blank.
- **File counts** are `project.fileCount` (the inventory count) — no `Map` over relations and no file rows in the store (ar-19: 2026 seeded `assets` rows and 2028 `belongs-to` relations gone, `localStorage['aluzina.data']` 3.66 MB -> 0.85 MB). The "N tagged" figure counts the project's curated rows (`curatedByProject` in `model.ts`, from the `belongs-to` relations `saveFilePatch` writes), so it now says how many files someone actually worked on rather than repeating the file count.
- **The Tag filter is the live union** of `projects[].tags`, so a tag saved on S-13 appears in the list without a reload and filtering by it finds the project at once (ar-09, verified in two tabs: tab A saved a new project tag through `archive.setProjectTags`, tab B's Tag `Select` gained the option and filtering by it returned the project — D-023).
- **The portfolio set** is an array of project ids in `localStorage['aluzina.archive.set']`, shared with S-13 through a window event and the `storage` event, so two mounted pages and two tabs agree. "Copy list" writes one line per project (`name · year · client · source link`) through `copyText`, in the order the projects were picked; when the clipboard is unavailable the toast says so and the list goes to the console rather than vanishing.
- **The set leaves the studio two ways** (ar-10 / ar-14). **Open example page** and **Export PDF** are anchors to P-06 — `<origin><path>#/sets?p=<ids in pick order>&t=<Ejemplos: N proyectos>` and the same with `&print=1`, both `target="_blank"` so middle-click and "open in new tab" behave — and P-06 calls `window.print()` once on the `print=1` link (verified: exactly 1 call). Because the page is stateless, the link needs no row: it *is* the set.
- **Save set to Spaces** (`spaces.write`) creates one `posts` row (`kind: 'link'`, title `Ejemplos: N proyectos`, `url` the P-06 link, body a markdown list of `name · year · type`, tags `portfolio` + `ejemplos`, `status: 'published'`, `authorId` the session user) and one `filings` row per existing target space (`sp-portfolio`, `sp-archive`); a missing space is skipped and the toast says the post is unfiled. The bar then shows **Open the saved set**, an anchor to `/<surface>/spaces/post/:id` — a toast is text only, so the link has to live somewhere the person can still click. The `studio` role does **not** have `spaces.write` today, so for Sarai the button is not rendered (request below).

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `archive.filterLifecycle` | Filter by lifecycle | show only {life} projects | `projects.read` | life: enum:prospect\|active\|past\|all |
| `archive.filterYear` | Filter by year | show only projects from {year} | `projects.read` | year: string |
| `archive.filterType` | Filter by project type | show only {type} projects | `projects.read` | type: enum:residential\|commercial\|hospitality\|wellness\|lighting-product\|all |
| `archive.filterTag` | Filter by tag | show only projects tagged {tag} | `projects.read` | tag: string |
| `archive.search` | Search the archive | find archived projects matching {q} | `projects.read` | q: string |
| `archive.setView` | Switch view | show the archive as {view} | `projects.read` | view: enum:cards\|table |
| `archive.openProject` | Open a project | open the portal view of the project {project} | `projects.read` | project: id |
| `archive.toggleInSet` | Add or remove from the portfolio set | put the project {project} in the portfolio set | `projects.read` | project: id |
| `archive.copySet` | Copy the portfolio set | copy the portfolio set as a list | `projects.read` | — |
| `archive.clearSet` | Clear the portfolio set | clear the portfolio set | `projects.read` | — |
| `archive.openSetPage` | Open the example page of the set | open the client-facing example page of the portfolio set | `projects.read` | — |
| `archive.exportSet` | Export the portfolio set | export the portfolio set as a PDF | `projects.read` | — |
| `archive.saveSetToSpaces` | Save the set to Spaces | save the portfolio set as a post in Spaces | `spaces.write` | — |
| `archive.importFolder` | Import a folder | import a Dropbox or Drive folder into the archive | `projects.read` | — |

All fourteen register while the page is mounted (`archive.saveSetToSpaces` only for a role that has `spaces.write`; it is not rendered otherwise, so there is nothing on screen that silently fails). `archive.openProject` and `archive.toggleInSet` accept either a project id or its name. `archive.openSetPage` and `archive.exportSet` are real since ar-14: they open P-06 (`/#/sets?p=…`, the second with `&print=1`) in a new tab and return the link, or `'the portfolio set is empty'` when nothing is selected. Only `archive.importFolder` is still a `Placeholder` answering `'not wired yet: …'` per D-047.
