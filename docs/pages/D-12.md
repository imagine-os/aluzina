# D-12 - Brand guidelines

- route: `/#/design`
- surface: design
- status: built
- spec: `apps/hub/src/modules/design/specs.ts` (`brandSpec`)

## Purpose

The brand manual alive inside the product. Anyone on the team (and the founder) opens one page and sees the marks, the four printed colours with their Pantone / HEX / RGB / CMYK, the metal switch, the gradients, the type specimen, the eight elements, the textures and the light / dark rules — all rendered from `src/design/tokens.ts` and the `BrandMark` atom, so the page cannot drift from the software the way a PDF does.

## Layout (top to bottom)

1. `PageHeader`: breadcrumb Design system / Brand guidelines, h1, subtitle.
2. **Logo**: wordmark metal on a forced-light tile, iridescent on a forced-dark tile, the descriptor lockup, and a Rules card (minimum height, clear space, "gold is never flat") with the two house rules labelled.
3. **Monogram**: periwinkle / aqua / lime stems plus metal and outline.
4. **Colors**: four diamond swatch cards (the manual's rotated squares) with Pantone, HEX, RGB, CMYK, role and a copy-hex button; notes for the `#F1D7AA` highlight, the `#231F20` ink and the pastel contrast warning.
5. **Metal finish**: gold / silver preview toggle, a live `Shimmer` metal band with the iridescent wordmark, and the note explaining the real one-line switch.
6. **Gradients**: the five gradient tokens as tiles.
7. **Typography**: a-z, A-Z, digits, the five weights, eyebrow / heading / body samples, the DIN Round Pro + Rubik fallback note.
8. **Elements**: the eight glyphs with their manual names.
9. **Textures**: the four pattern tiles and the metal / iridescent / outline circles.
10. **Light and dark**: the same sample card in both themes side by side.
11. **What the manual does not define**, then the source line.

## Logic

- Colours come from `tokens.brand`, gradients from `var(--gradient-*)`, marks from `BrandMark`: no hard-coded hex in the page except the print data (RGB / CMYK strings) the manual prints.
- The metal toggle writes `<html data-metal>` and `aluzina.metal`; `modules/design/metal.ts` re-applies it on boot (the module is imported eagerly by the route registry), so the preview survives a reload.
- The light / dark plates are `data-theme="light|dark"` wrappers: `tokens.css` redeclares every `--color-*` under `[data-theme]`, so components inside render in that theme whatever the header toggle says.
- Copy hex uses `navigator.clipboard` and toasts either the value or "select it and copy by hand" when the API is blocked.

## Real vs mock / placeholder

All real. No placeholders: every control on the page does what it says. The silver values are provisional (Pantone 877 C candidate) and the page says so; DIN Round Pro is not in the repository, so the specimen renders in the fallback until the licensed files land in `public/fonts/`.

## Responsive and input check (P-01, P-03)

Verified at 390, 1280, 1920 in both themes (`checkedAt`). No horizontal overflow at any width (checked in the capture script). Marks letterbox instead of clipping (`max-width: 100%` on the SVG) and step down a size band under 1024. Keyboard: header → metal toggles → copy buttons, all >= 44 px, global focus ring; nothing hover-only. 2560 / 3840 inherit the `--scale` bands (1.5 / 2) and were not captured this pass.

## Strings (P-13)

Namespace `design.*` + `core.*`. EN complete, ES complete. The element names (FUEGO … ARTE) and the print data are brand constants, not translated.
