# K-03 - Post

- route: `/#/<surface>/spaces/post/:postId` (founder, ops, studio, brand, dev)
- surface: founder | ops | studio | brand | dev
- status: built
- spec: `apps/hub/src/modules/spaces/specs.ts` (`postSpec(surface)`)
- model: Fable 5.1

## Purpose

One post: its Markdown body, the spaces it is filed in (add or remove without duplicating it), tags, typed relations to any entity, what references it (backlinks), comments and the activity trail. This is where "belongs in more than one place" and "can reference each other smartly" (prompt 0005) are operated.

## Layout (top to bottom)

1. `PageHeader`: title; breadcrumb Portal > Spaces > first filed space > post; actions Preview (a file post whose file can be shown in place, ar-17), Open link (link posts, and file posts with nothing to preview), Pin / Unpin, Edit, status `Select` (draft / published / archived) for `spaces.write`.
2. Meta row: kind pill, status pill (when not published), Pinned badge, author `Avatar` + name, "Updated <date>", tags.
3. File block (`kind: 'file'` only, ar-17): a `Thumb` of the file (served thumbnail, `FileIcon` of the family otherwise), its file-type name, the page count when there are served renders, and either **Preview** (opens a `Drawer` with the shared `DocumentViewer`) or the sentence "This file cannot be shown here; open it at the source." plus the post's link and the file's source link.
4. Body: `Markdown`; in edit mode a form (title `Input`, body `Textarea` with Markdown hint, tags `Input`) with Save / Cancel.
5. Comments: thread + `Textarea` + Comment button (all roles with `spaces.read`).
6. Aside: Filed in (chips linking to each space, × to remove, "File in…" opens a `Drawer` with a search and one `Checkbox` per space, indented path labels); Relations (kind pill, target button, type, ×; add form: type `Select` over 13 entity types, target `SearchField` with result buttons, kind `Select`, note `Input`, Add); Referenced by (reverse query); Activity (provider `activity` rows, newest first).

## Data

Reads `posts`, `filings`, `spaces`, `relations` (from and to), `comments`, `activity`, `assets` (ar-17: the file a `file` post points at), and for the entity index `projects`, `tasks`, `documents`, `clients`, `deliverables`, `tools`, `competitions`, `brandAssets`, `presentations` (+ roles and demo users). Writes `posts` (title, body, tags, pinned, status), `filings` (create / remove), `relations` (create / remove), `comments` (create).

## Rules

None numbered. A post keeps at least one filing (removing the last one is refused with a toast). Draft / archived posts are visible to the author and to `spaces.write` roles.

## Logic

- Filing adds or removes a `filings` row; the post stays one row, so an edit here shows in every space at once (the aside says so).
- Relations are typed and any-to-any; "Referenced by" lists relations whose target is this post. Opening a target navigates to its route from the entity index (`entities.ts`); entities without a page toast "no page yet".
- Edits write with `basedOn = post.updated_at` (D-024); the provider appends `activity` rows per changed field (D-022); other tabs re-render from the broadcast (D-023).
- The Markdown renderer builds React elements only; non-http links render as text.
- **The file of a file post** (ar-17) is the first `assets` row among the post's outgoing relations. It previews in place when that row has served page renders, or is a served PDF, image or video (`isPreviewable`, `domain/archive.ts`): **Preview** opens the page's `Drawer` around the shared `DocumentViewer` and replaces the bare "Open link" in the header. Anything else keeps its link - for the archived Dropbox files, redacted by D-059 and never served, the link is the only way to the file, and the block says so in a sentence instead of showing a broken image.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `spaces.editPost` / `spaces.savePost` | Edit / Save post | edit / save the post {post} | `spaces.write` | `post`, `title`, `body` |
| `spaces.pin` | Pin or unpin | pin the post {post} | `spaces.write` | `post: id` |
| `spaces.setStatus` | Publish / archive post | set the post {post} to {status} | `spaces.write` | `status: enum:draft\|published\|archived` |
| `spaces.fileIn` / `spaces.unfile` | File in / remove from space | file the post {post} in {space} | `spaces.write` | `post, space` |
| `spaces.setTags` | Edit tags | tag the post {post} with {tags} | `spaces.write` | `tags: string` |
| `spaces.relate` / `spaces.unrelate` | Add / remove relation | relate the post {post} to the {type} {target} as {kind} | `spaces.write` | `type, target, kind` / `relation` |
| `spaces.openTarget` | Open related entity | open the {type} {target} | `spaces.read` | `type, target` |
| `spaces.comment` | Comment | comment on the post {post}: {text} | `spaces.read` | `text` |
| `spaces.openLink` | Open link | open the link of the post {post} | `spaces.read` | `post` |
| `spaces.selectSpace` | Open space | open the space {space} | `spaces.read` | `space` |
| `spaces.previewAsset` | Preview the file | preview the file of this post | `spaces.read` | `asset: id` |
| `spaces.closeAssetPreview` | Close the preview | close the file preview | `spaces.read` | — |

`spaces.previewAsset` and `spaces.closeAssetPreview` (ar-17) register while the page is mounted. On a post with nothing to preview the handler answers `'not previewable: this post has no file the browser can show; its link opens it at the source'` rather than failing silently (D-047).

## Real vs mock / placeholder

Everything is real through the DataProvider. No `Placeholder`. Not built: file attachments (storage), post versions, mentions in comments. The ar-17 preview branch is real but **has no data yet**: no seeded `file` post relates to an `assets` row (the six archived invoice posts carry only a Dropbox `url`, and the one template post relates to a `brandAssets` row), so today every file post renders the icon + link branch. The same viewer on the same rows is exercised on K-05 and G-08.
