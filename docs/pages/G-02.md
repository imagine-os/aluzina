## Data

Reads and writes `competitions` (name, organiser, category, submissionDate, project, materialsFolder, result, status) through `useData().update`.

## Rules

The unknown rule (`docs/knowledge/competitions.md`): the seed leaves every fact null except the three named projects and their folders; nulls render as *unknown* in muted italics, never as a guessed date or name. Submission-date ordering is the founder's rule. P-01, P-03, P-05, P-09, P-13.

## Logic

- Sort: `submissionDate` ascending, nulls last, `slot` as the tiebreak (`helpers.tsx#byDateThen`). The table's own sort uses `9999-12-31` as the null sort value so clicking the header keeps undated slots last.
- Status advances one step along `slot -> researching -> preparing -> ready -> submitted -> result`; at `result` the action disappears.
- Saving writes empty strings back as `null`, so clearing a field returns it to unknown instead of storing `""`.
- The Calendar renders only dated slots. With no dates shared it shows its empty state, which is the honest picture; it starts on 2027-01.
- The list keeps six columns so everything fits at 1280 px; organiser and category are in the drawer.
