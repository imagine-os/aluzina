# M-01 - Operations manual

- route: `/#/manual`
- surface: manual
- status: built
- spec: `apps/hub/src/modules/manual/specs.ts` (`overviewSpec`)
- model: Opus 5

## Purpose

The front page of the operations manual: what the method is for, the ten-step client journey every service shares, the five-rung service ladder with a way into each service, how many governance rules hold it together, and quick links to the commercial process, the status architecture and the KPI layer. Every role holds `manual.read`, so this is the one page in the Hub that anybody can open to answer "how does ALUZINA work?".

## Layout (top to bottom)

1. `PageHeader`: "Operations manual", subtitle, **Print / PDF** action.
2. Motto banner: "One studio. One method. Different depths of service."
3. What this manual is for + the source line (`docs/knowledge/service-playbook.md`).
4. Core client journey: the 10 `CLIENT_JOURNEY` steps as a numbered stepper that wraps.
5. The ALUZINA service ladder: `SERVICE_LADDER_LOGIC` plus 5 rows (code badge, service name, arrow, ladder word, "Open <service>").
6. Two cards: Governance (rule count, link to M-08) and Quick links (commercial process, status architecture, KPI layer).
7. Final principle as a pull quote.

## Rules

None enforced here. The page counts and links the governance rules; M-08 renders them.

## Logic

- No copy of the playbook lives in this module: the strings table holds UI labels only, the founder's wording comes from the domain data, so a correction in `playbook.ts` shows here and in the product at once.
- The quick links carry `?s=<section>` so the governance page scrolls to the section that was asked for (state in the URL, P-06).
- Print / PDF calls `window.print()`; `manual.css` hides `.manual-noprint` chrome in the print media query.

## Components

`PageHeader`, `Card`, `Button`, `Badge`.

## Real vs mock / placeholder

Everything is real: the content is the playbook data and Print / PDF really prints. No `Placeholder` on this page. No mock data (the manual reads no entities).

## Responsive and input check (P-01, P-03)

Verified with Playwright at 360 / 390 / 768 / 1280 / 1920 / 2560 / 3840 (`spec.checkedAt`), light and dark, EN and ES: no horizontal page overflow at any width, no console errors (the only console entry is the dev server's font certificate). Focus order follows the reading order; every control is a library `Button` or `Select` (>= 44 px) with the global focus ring; nothing is hover-only or drag-only. At 2560 / 3840 the `--scale` bands do the work and the reading measure widens (`max-width` 72rem -> 90rem, body text one step up). The stepper wraps instead of scrolling sideways, so a phone never hides a step.

## Strings (P-13)

`manual.*` (shared across M-01..M-08); EN and ES complete. The document text itself is `{ en, es? }` in `playbook.ts`: Spanish is complete there except where the integrator left the English fallback.
