# G-03 - Sales presentations

- route: `/#/brand/presentations`
- surface: brand
- status: built
- spec: `apps/hub/src/modules/brand/specs.ts` (`presentationsSpec`)
- model: Opus 5

## Purpose

"Sales presentations" from Angélica's roster, widened to every deck she produces: sales, concept, proposal and competition. One list from requested to final, with the project, the slide count and the due date.

## Screenshots

Check captures: `shots/brand/G-03-en-390.png`, `G-03-en-1280.png`. Repo set: integrator pass.

## Layout (top to bottom)

1. `PageHeader` with "Request a deck" (`Placeholder`).
2. Four `StatTile`s: open, in review, final, overdue.
3. `FilterBar`: search + kind + status.
4. `DataTable`: presentation, project, kind, slides, due, status, with an Advance row action.
5. `Drawer`: detail (`KeyValue`), Advance, "Open the file" (`Placeholder`).

## Data

Reads `presentations` and `projects` (for names); writes `presentations.status`.

## Rules

P-01, P-03, P-05, P-09, P-13. A slide count of 0 is shown as *not started* rather than as a zero-slide deck.

## Logic

- Flow `requested -> drafting -> review -> final`; the action disappears at final.
- Overdue = `dueDate` in the past and status not final.
- Default sort is by due date with undated decks last.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `brand.openPresentation` | Open presentation | open the presentation {presentation} | `presentations.write` | presentation: id |
| `brand.advancePresentation` | Advance presentation | move the presentation {presentation} to the next status | `presentations.write` | presentation: id |
| `brand.requestPresentation` | Request a presentation | request a {kind} presentation for {project} | `presentations.write` | kind: enum, project: id |
| `brand.openDeck` | Open the deck file | open the deck file of {presentation} | `presentations.write` | presentation: id |
