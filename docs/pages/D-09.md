## Purpose

The actions bus as a page. Every action declared in a `PageSpec` (`spec.actions`) is joined with the handlers registered right now by mounted pages, so a builder can see the whole control vocabulary, filter it, run one by id through a generated parameter form, and copy it as a WebMCP tool definition. This is what makes P-05 / P-06 / D-036 inspectable: the same list a voice controller or an MCP server will read is on screen, with a "live" column that says whether anything is listening.

## Layout (top to bottom)

1. DesktopShell (dev surface, `dev.tools`).
2. `PageHeader`: breadcrumb, title, subtitle, "Export all as JSON" primary button.
3. Five `StatTile`s: declared, distinct ids, live now, with permission, with params.
4. `FilterBar`: `SearchField` (id, label, intent, code, path, page name), surface `Select`, module `Select` (the id prefix), permission `Select` (plus "No permission"), "Live only" `Checkbox`, summary, Clear.
5. `DataTable`: action id, page (code + path), label, intent, permission, params, live `Badge`. Sortable, rows focusable.
6. `Drawer` (row activation): the full `ActionDef` as `KeyValue`, the generated parameter form, an inline result / error block, the WebMCP tool JSON, and a footer with Run, Copy as WebMCP tool JSON, Open the page.

## Data

None. Routes come from `RoutesContext`; the declared list is `declaredActions(routes)` and the live list is `useLiveActions()` (`src/actions`).

## Rules

None (governance rules live on the pages whose actions are listed).

## Logic

- Rows are `declaredActions(useRoutes())` joined to the route by path, so each row also carries the surface and the page name (`DeclaredAction` itself carries neither).
- The live column re-renders from `subscribeLiveActions`, so navigating changes it live; only the currently mounted pages have handlers.
- The parameter form is generated from `ActionDef.params`: `string` / `id` -> text `Input`, `number` -> number `Input`, `date` -> date `Input`, `boolean` -> `Checkbox`, `enum:a|b|c` -> `Select`. Empty non-boolean fields are omitted from the call.
- **Run** calls `runAction(id, params)` and renders the `ActionResult`; it is disabled while the id is not live or `can(permission)` is false, and the drawer says which of the two blocked it.
- **Copy as WebMCP tool JSON** writes `{ name: id, description: intent, inputSchema: { type: 'object', properties } }`; `ParamType` maps to JSON Schema (`enum:` -> `{ type: 'string', enum: [...] }`, `date` -> `{ type: 'string', format: 'date' }`, `id` -> `{ type: 'string', description: 'row id' }`).
- **Export all as JSON** downloads a Blob with `{ generatedAt, count, actions, tools }` — every declared row plus one tool per distinct id.
- `qa.runAction` refuses to run itself so the bus cannot recurse.
- The clipboard is optional: `copyText()` returns false on an insecure origin or a browser without `navigator.clipboard`, and the toast says so.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `qa.searchActions` | Search actions | find the action {query} | `dev.tools` | `query: string` |
| `qa.filterActionsSurface` | Filter actions by surface | show only actions of the {surface} surface | `dev.tools` | `surface: enum:all\|hub\|founder\|ops\|studio\|brand\|client\|dev\|docs\|manual\|public` |
| `qa.filterActionsLive` | Show only live actions | show only the actions that are live right now | `dev.tools` | `live: boolean` |
| `qa.openAction` | Open an action | open the action {action} | `dev.tools` | `action: id` |
| `qa.runAction` | Run an action | run the action {action} | `dev.tools` | `action: id` (extra keys pass through as the target's params) |
| `qa.copyActionTool` | Copy an action as a WebMCP tool | copy the action {action} as a WebMCP tool definition | `dev.tools` | `action: id` |
| `qa.exportActions` | Export every action | export every declared action as JSON | `dev.tools` | — |

All seven are registered while the page is mounted, so the page lists itself as live.

## Responsive and input check (P-01, P-03)

Verified with Playwright (Chromium 1194) at 360 / 390 / 768 / 1280 / 1920 / 2560 / 3840 against `vite`: `scrollWidth === clientWidth` at every width (no page overflow), no console or page errors, no missing-translation markers, root font size 16 / 16 / 16 / 16 / 18 / 24 / 32 px as the bands promise. The `DataTable` collapses to stacked cards under 768. The only sub-44 px element is the native `input.check__box` of the "Live only" `Checkbox` (24 px); its `<label>` hit area measures 44 px, which is the WCAG 2.5.8 target and matches the resolution recorded in `docs/qa/0001-work-views-matrix.md` (fix 3). Keyboard: Tab reaches the export button, every filter, the sort headers and the rows; Enter opens the drawer, Escape closes it and returns focus; the drawer traps focus (`useFocusTrap`). Row activation, filling a param and running an action were exercised end to end in Chromium.
