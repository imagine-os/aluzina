# G-05 - Images for clients

- route: `/#/brand/images`
- surface: brand
- status: built
- spec: `apps/hub/src/modules/brand/specs.ts` (`imagesSpec`)
- model: Opus 5

## Purpose

"Preparing images for clients" from Angélica's roster: the image sets she produces per project - renders, progress photos, retouching - from the request through delivery to the client's approval.

## Screenshots

Check captures: `shots/brand/G-05-en-390.png`, `G-05-en-1280.png`. Repo set: integrator pass.

## Layout (top to bottom)

1. `PageHeader` with "New image set" (`Placeholder`).
2. Four `StatTile`s, one per status.
3. `FilterBar`: search + status.
4. One `Card` per project, each with a dense `DataTable` of its image sets and an Advance row action.
5. `Drawer`: detail (`KeyValue`), Advance, "Share with the client" (`Placeholder`), image thumbnails (`Placeholder`).

## Data

Reads `revisions` where `kind = image`, plus `projects` for names; writes `revisions.status`.

## Rules

P-01, P-03, P-05, P-09, P-13. Only `kind = image` appears here; the other kinds belong to G-06, so nothing is listed twice.

## Logic

- Grouped by project; sets without a project fall into a "no project" card.
- Flow `requested -> in-progress -> delivered -> approved`. Client approval is not wired: today advancing to `approved` is Angélica recording it.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `brand.openImageSet` | Open image set | open the image set {revision} | `images.write` | revision: id |
| `brand.advanceImageSet` | Advance image set | move the image set {revision} to the next status | `images.write` | revision: id |
| `brand.newImageSet` | New image set | prepare a new image set for {project} | `images.write` | project: id |
| `brand.shareImages` | Share with the client | share the image set {revision} with the client | `images.write` | revision: id |
| `brand.previewImages` | Preview the images | preview the images of {revision} | `images.write` | revision: id |
