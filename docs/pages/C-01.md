# C-01 - Client home

- route: `/#/client`
- surface: client (PhoneShell)
- status: built
- spec: `apps/hub/src/modules/client/specs.ts` (`homeSpec`)
- model: Opus 5

## Purpose

The first screen of the customer app. The person who hired ALUZINA opens it and sees, without scrolling far: how their project stands today, what is waiting for *them*, and where they are in the ten-step client journey of the playbook. Everything else in the client app is reached from here or from the bottom nav.

`docs/screenshots/C-01/en-390.jpg`, `en-1280.jpg`, `es-390.jpg` — captures taken against the dev server at 390 (EN and ES, light and dark) and 1280; the integrator runs `npm run screenshots` for the repo copies.

## Layout (top to bottom)

1. `PageHeader` (C-01): the greeting "Hello, {name}" and the subtitle.
2. One `Card` per project (the whole card is one button opening C-02): project name, service name, pipeline `StatusPill`, current phase `Badge`, progress bar with "66 of 119 steps done (55%)", and the next step.
3. `Card` "Waiting for you": three `StatTile`s — comments to decide (opens C-03), unread messages (C-04), pending payments with the outstanding amount (C-05).
4. `Card` "Your journey": the ten `CLIENT_JOURNEY` steps, done ones ticked, the current one bold with a "You are here" badge (project `Select` above it when the client has more than one project).
5. `Card` "Not your project?": the data-scope note and a shortcut into Messages.

## Data

Reads `projects` (scoped to `clientUserId`), `engagements`, `revisionItems`, `messages`, `payments`. Writes nothing.

## Rules

Playbook client journey (p. 2) and the 15-status pipeline (p. 17, D-033). The client's data scope is the rule that matters: only `projects.clientUserId === session user`.

## Logic

- `useMyProjects()` is the single scope: it loads my projects, pairs each with its `engagements` row and computes progress, current phase, next step and journey index. Every other query on the page filters on `projectIds`.
- Progress = ticked `engagements.checks` over `phaseItems()` of every phase of the service, so it is the playbook checklist, not a guess.
- Next step = the first unticked item of the current phase, else "Starting: <next phase>", else "everything done".
- Comments to decide = `revisionItems` of my projects with `decidedAt === null`. Unread = messages not written by me whose `readBy` lacks my id (my own messages never count). Pending payments = `direction: 'in'` and `status !== 'paid'`, with the outstanding sum in COP.
- The journey step maps `projects.pipelineStatus` onto `CLIENT_JOURNEY` (several studio statuses share one client-facing step; `contracted` shows as Diagnosis, `client-review` and `approved` as Validation, procurement / construction / punch-list / delivered as Delivery).

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `client.openProject` | Open project | open my project {project} | `own.projects.read` | `project: id` |
| `client.openApprovals` | Open approvals | show the comments waiting for my decision | `own.projects.read` | — |
| `client.openMessages` | Open messages | open my conversation with the studio | `own.projects.read` | — |
| `client.selectProject` | Select project | focus on my project {project} | `own.projects.read` | `project: id` |

All four are registered while the page is mounted; `window.__aluzina.actions.run('client.openMessages')` navigates.

## Components

`PageHeader`, `Card`, `StatTile`, `StatusPill`, `Badge`, `Button`, `Select`, `EmptyState`, `Skeleton`. The progress bar and the journey stepper are local markup over tokens (requested for the library: `ProgressBar`, `Stepper`).

## Real vs mock / placeholder

All real, no `Placeholder`. Data is the seeded demo: the client demo user `u-client` owns Casa Laureles, so the page shows one project, 2 comments to decide, 1 unread message and COP 18,500,000 outstanding.

## Responsive and input check (P-01, P-03)

Verified at 360 / 390 / 768 / 1280 / 1920, light and dark, EN and ES: no horizontal overflow at any width, every control at least 44 px tall, focus ring 3 px on every focusable, tab order top to bottom, nothing hover-only. The PhoneShell centres a 30 rem column, so 2560 / 3840 show the same column larger through the `--scale` bands.

## Strings (P-13)

Namespace `client.home.*` and `client.common.*` (plus `core.status.*`). EN complete, ES complete.

## Open questions

- With several projects the journey card shows one at a time; a client with two live projects may want both stacked.
- "Unread" is per person (`messages.readBy`); a real notification badge in the shell would need the same count at the app level.
