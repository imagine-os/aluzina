# S-05 - Plans and design documentation

- route: `/#/studio/plans`
- surface: studio
- status: built
- spec: `apps/hub/src/modules/studio/specs.ts` (`plansSpec`)
- model: Opus 5

## Purpose

The drawings and specifications the studio owns: which project they belong to, which version is current, who owns them and whether they are still a draft. Contracts, invoices and client PDFs stay in the operations and founder portals.

## Screenshots

Not captured in this pass; working captures at 390 and 1280 in the worker scratchpad.

## Layout (top to bottom)

1. `PageHeader` with a `Placeholder` "Upload drawing".
2. Three `StatTile`s: plans and specs, still draft, final.
3. `FilterBar`: `SearchField`, project `Select`, status `Select`.
4. `DataTable`: title, project, kind, version, owner, status; row actions "New version" and "Mark final".
5. `Drawer`: project, kind, version, owner, status, last change, file.

## Data

Reads `documents` (kinds `plan` and `spec`), `projects`. Writes `documents.version` and `documents.status`.

## Rules

A new version resets the document to `draft` (version numbers only ever go up). "Mark final" is offered only for a draft. Both need `plans.write`.

## Logic

- The page filters `documents` by kind rather than by owner, so a plan owned by another role is still visible to the studio.
- `url` is null in every seed row: the detail says "No file attached" and opening the file is a `Placeholder`.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `studio.newPlanVersion` | New version | create a new version of the plan {document} | `plans.write` | `document: id` |
| `studio.finalisePlan` | Mark final | mark the plan {document} as final | `plans.write` | `document: id` |
| `studio.openPlan` | Open document | open the plan {document} | `plans.write` | `document: id` |
| `studio.uploadDrawing` | Upload drawing | upload a drawing file for {project} | `plans.write` | `project: id` |
