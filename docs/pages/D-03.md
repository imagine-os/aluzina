# D-03 - Page specs

- route: `/#/dev/specs`
- surface: dev
- status: built
- spec: `apps/hub/src/modules/dev/specs.ts` (`specsSpec`)
- model: Fable 5.1

## Purpose

Every registered route with status, surface, roles, action count and spec completeness, plus a drawer with the full `PageSpec` and its actions. It is the human view of `window.__aluzina.routes` (P-05, P-11) and the place to see which portal pages are still stubs.

## Screenshots

`docs/screenshots/D-03/en-390.jpg`, `en-1280.jpg` (live site, changelog 0006).

## Layout (top to bottom)

1. DesktopShell (as D-02).
2. `PageHeader`: breadcrumb, h1, subtitle.
3. Four `StatTile`s: routes, built, stubs, actions declared.
4. `FilterBar`: `SearchField` (code, name, path, roles), surface `Select`, summary, Clear.
5. `DataTable`: code, page, path, surface, status (`StatusPill`), roles, actions, spec (`Badge` n/9); sortable; rows focusable.
6. `Drawer` (row activation): purpose, `KeyValue` (path, surface, status, shell, permission, roles, nav group, data tables, components, verified widths, completeness), layout list, logic list, actions with intent / permission / params.

## Data

None (routes from `RoutesContext`; `specCompleteness()` from `src/specs/PageSpec.ts`).

## Rules

None.

## Logic

- Completeness = 9 checks: purpose > 20 chars, layout, roles, logic, components, >= 1 action, >= 3 verified widths, navGroup when in the menu, status built. Green when 9/9, accent >= 6, warning below.
- ArrowUp / ArrowDown move between rows, Enter / Space or click opens the drawer, Escape closes it and returns focus to the row.
- Guarded by `dev.tools`.

## Actions (P-05)

| `dev.filterSurface` | Filter by surface | show only {surface} pages | `dev.tools` | `surface: enum:all\|hub\|founder\|ops\|studio\|brand\|client\|dev\|docs\|manual\|public` |
