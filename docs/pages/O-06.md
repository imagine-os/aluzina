# O-06 - Deliveries and dates

- route: `/#/ops/deliveries`
- surface: ops
- status: built
- spec: `apps/hub/src/modules/ops/specs.ts` (`deliveriesSpec`)
- model: Opus 5

## Purpose

"Confirming deliveries and dates": what each supplier owes each project, the date we expect it, the date the supplier actually confirmed, and whether it arrived or slipped.

## Screenshots

`docs/screenshots/O-06/en-390.jpg`, `en-1280.jpg` — captured by the integrator.

## Layout (top to bottom)

1. `PageHeader` (O-06).
2. `FilterBar`: search (item, supplier), project select, status select, count, clear.
3. `DataTable` sorted by expected date: item, supplier, project, expected (with the days-left line), confirmed, status; row actions Confirm date / Mark received / Flag as delayed.
4. `Modal` "Confirm delivery date" with a date input.

## Data

Reads `deliveries`, `suppliers`, `projects`. Writes `deliveries.confirmedDate` and `deliveries.status`.

## Rules

None numbered yet.

## Logic

- Confirm opens the modal with the date defaulted to the confirmed date if there is one, else the expected date; saving writes `confirmedDate` and `status = 'confirmed'`.
- Mark received writes `status = 'delivered'` and fills `confirmedDate` when it was still empty.
- Flag as delayed writes `status = 'delayed'` and clears `confirmedDate`, because the promised date is no longer true.
- The expected column always carries "due today" / "in n days" / "n days overdue".
