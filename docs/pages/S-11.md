## Purpose

Stage 10 of service 03 says: present the scheme, **collect all comments in one revision matrix**, avoid scattered design changes through WhatsApp, assign an approval status. This page is that matrix: one table per project, one row per comment, each with its source (client / studio / founder), its author and its validation status. G-05 in the product.

## Layout (top to bottom)

1. `PageHeader` with the `Placeholder` "Send to client" and the real "Export matrix".
2. `FilterBar`: project `Select`, stage, status, source, with the `n of m` summary and Clear filters.
3. Three `StatTile`s: open revisions (`revision`), approved, approved with adjustments.
4. `Card` (only when the matrix is decided): the client can approve the design for execution from the client app.
5. `Card` "Matrix": `DataTable` of `revisionItems` — stage, item, comment, source `Badge`, author, status `StatusPill`, decided date. Row activation opens the drawer.
6. `Card` "Add item": stage `Select` (the phases of the project's service plus every label already used), item `Input`, comment `Textarea`, the "signed as …" line and the Add item submit.
7. `Drawer`: the row's `KeyValue`, the comment `Textarea` with Save, the three validation status buttons and the "Resolve as adjustment" shortcut.

## Data

Reads `revisionItems`, `projects`, `engagements` and the playbook phases. Creates `revisionItems`; writes `revisionItems.comment`, `.status`, `.decidedAt`. Updates carry `{ basedOn: row.updated_at }` (D-024).

## Rules

- **G-05**: design revisions are consolidated into a single revision matrix. Every comment is a row here; nothing is stored as free text on the project.
- **G-03**: client approvals are documented — the status and `decidedAt` of each row are the record.
- Validation statuses are `VALIDATION_STATUSES` (`approved`, `approved-with-adjustments`, `revision`); setting one writes `decidedAt = today`, and moving a row back to `revision` clears it.
- Every write needs `revisionMatrix.write`; without it the table is read-only, the add form is not rendered and the drawer's controls are hidden.

## Logic

- The project defaults to the first project that already has a matrix, otherwise the first project with an engagement.
- A new row is signed with the writer's role: founder → `founder`, client → `client`, everyone else → `studio`; `authorId` is the session user, status starts as `revision` with no `decidedAt`.
- The stage `Select` offers `<number>. <title>` for each phase of the project's service (from the playbook) plus every stage label already used on the matrix, so the matrix stays comparable without a new entity; `stage` itself stays a free label as the schema defines it.
- "Export matrix" builds a real CSV from the filtered rows — UTF-8 BOM, CRLF line ends, RFC 4180 quoting — and downloads it through a `Blob` URL as `revision-matrix-<project>.csv`. Verified: the downloaded file opens with the seven translated headers and the accented Spanish comments intact.
- The "matrix decided" note appears when no row is left in `revision` **and** the project approval is `awaiting-founder` or `approved`: at that point the client can approve for execution in the client app (C-03).
- Filters are client-side over the live table; the drawer's comment is edited locally and written on Save, so a half-typed comment never lands in the matrix.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `studio.selectRevisionProject` | Choose project | show the revision matrix of {project} | `revisionMatrix.write` | `project: id` |
| `studio.filterRevisions` | Filter matrix | filter the matrix by stage {stage}, status {status} and source {source} | `revisionMatrix.write` | `stage: string`, `status: enum`, `source: enum` |
| `studio.addRevisionItem` | Add item | add the comment {comment} about {item} at stage {stage} to the matrix | `revisionMatrix.write` | `stage: string`, `item: string`, `comment: string` |
| `studio.editRevisionItem` | Save comment | change the comment of the matrix item {item} | `revisionMatrix.write` | `item: id`, `comment: string` |
| `studio.setRevisionStatus` | Set status | set the matrix item {item} to {status} | `revisionMatrix.write` | `item: id`, `status: enum` |
| `studio.exportRevisionMatrix` | Export matrix | export the revision matrix as a CSV file | `revisionMatrix.write` | — |
| `studio.sendMatrixToClient` | Send to client | send the revision matrix to the client | `revisionMatrix.write` | `project: id` |

Six register while mounted; `studio.sendMatrixToClient` is declared but **not** registered, because the control is a `Placeholder` (D-09 will show it as declared-not-live, which is the honest state).
