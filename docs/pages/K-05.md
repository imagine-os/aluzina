# K-05 - Catalog

- route: `/#/<surface>/spaces/catalog` (founder, ops, studio, brand, dev); `?tab=deliverables|clients|tools|roles`
- surface: founder | ops | studio | brand | dev
- status: built
- spec: `apps/hub/src/modules/spaces/specs.ts` (`catalogSpec(surface)`)
- model: Fable 5.1

## Purpose

The catalogs behind the spaces as data (D-029): deliverable types with phase, owner and template status; clients past / current / prospect with their projects; the tools the studio pays for and which hub module replaces each (the dependency map for "own the whole platform", D-030); the roles with their portals. Justin said these lists are only started; here they are rows to complete, not prose.

## Screenshots

`docs/screenshots/K-05/en-390.jpg`, `en-1280.jpg` (live, Deliverables tab).

## Layout (top to bottom)

1. `PageHeader`.
2. `Tabs` with counts: Deliverables (25), Clients (6), Tools (9), Roles (7).
3. Deliverables: hint + `DataTable` (name, phase, owner, typical days, status, relations, template: "Open <code>" link when the template is a hub page, else `Placeholder` "Open template").
4. Clients: hint + `DataTable` (name, kind pill, sector, city, contact, projects as Work links, relations, space link); unknowns render as "unknown".
5. Tools: `StatTile` dependency map (in use, to replace, replaced, planned) + `DataTable` (name, vendor, category, used for, status, replaced by -> route link when it starts with a page code, notes).
6. Roles: `DataTable` (role, portal link, dashboard code, permissions count, demo user, role space); Enter / click opens the portal.

## Data

Reads `deliverables`, `clients`, `tools`, `relations` (counts), `spaces` (about-spaces), `projects` (names). No writes yet.

## Rules

None numbered. Facts that are unknown are `null` in data and "unknown" on screen, never guessed.

## Logic

- Template and "replaced by" values that start with a page code (`S-09`, `W-01`, `K-01`, …) resolve to a route from the manifest (preferring the current surface); others show a Placeholder (P-09) or plain text.
- Roles come from `src/auth/roles.ts` (seven since D-028) and `permissions.ts`; the role space is the space with `aboutType = roles`.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `spaces.catalogTab` | Catalog tab | show the {tab} catalog | `spaces.read` | `tab: enum:deliverables\|clients\|tools\|roles` |
| `spaces.openTemplate` | Open template | open the template of the deliverable {deliverable} | `spaces.read` | `deliverable: id` (Placeholder) |
| `spaces.openRoute` | Open hub page | open the hub page {code} | `spaces.read` | `code: string` |
| `spaces.selectSpace` | Open space | open the space {space} | `spaces.read` | `space: id` |
| `spaces.openProject` | Open project work | open the work of the project {project} | `spaces.read` | `project: id` |
