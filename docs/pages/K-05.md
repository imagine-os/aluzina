## Purpose

The catalogs behind the spaces as data (D-029): deliverable types with phase, owner and template status; clients past / current / prospect with their projects; the tools the studio pays for and which hub module replaces each (the dependency map for "own the whole platform", D-030); the roles with their portals. Justin said these lists are only started; here they are rows to complete, not prose.

## Layout (top to bottom)

1. `PageHeader`.
2. `Tabs` with counts: Deliverables (27), Clients (12), Tools (9), Roles (7), Assets (14).
3. Deliverables: hint + `DataTable` (name, phase, owner, typical days, status, relations, template: "Open <code>" link when the template is a hub page, else `Placeholder` "Open template").
4. Clients: hint + `DataTable` (name, kind pill, sector, city, contact, projects as Work links, relations, space link); unknowns render as "unknown".
5. Tools: `StatTile` dependency map (in use, to replace, replaced, planned) + `DataTable` (name, vendor, category, used for, status, replaced by -> route link when it starts with a page code, notes).
6. Roles: `DataTable` (role, portal link, dashboard code, permissions count, demo user, role space); Enter / click opens the portal.
7. **Assets** (ar-17): hint + `DataTable` (a `Thumb` per row, name, kind badge, file type, pages, source, relations, and an Open cell with **Preview** / the G-08 link for a document / **Open at source**). Enter or a click on the row previews it. A `Drawer` under the tabs holds the shared `DocumentViewer` plus Download / Open at source / Close.

## Data

Reads `deliverables`, `clients`, `tools`, `relations` (counts), `spaces` (about-spaces), `projects` (names) and, since ar-17, `assets`. No writes.

The Assets tab lists the `assets` rows that are files in their own right, `kind != 'page'` (a `page` row is a render **inside** a document, not a file): today the 2 marketing PDFs (`kind: 'document'`) and the 12 company documents of ar-15 (`kind: 'file'`) - 14 rows. Archived project files are deliberately absent: since ar-19 they are not `assets` rows at all, they load lazily per project and S-12 / S-13 are their browser.

## Rules

None numbered. Facts that are unknown are `null` in data and "unknown" on screen, never guessed.

## Logic

- Template and "replaced by" values that start with a page code (`S-09`, `W-01`, `K-01`, …) resolve to a route from the manifest (preferring the current surface); others show a Placeholder (P-09) or plain text.
- Roles come from `src/auth/roles.ts` (seven since D-028) and `permissions.ts`; the role space is the space with `aboutType = roles`.
- **Assets** (ar-17): every row shows a `Thumb` - the served thumbnail, or the `FileIcon` of the family read from `sourceName ?? title` (`fileTypeOf`), never a broken image. A row previews in place when it has served page renders, or is a served PDF, image or video (`isPreviewable`); the `Drawer` then holds the shared `DocumentViewer` (paged image viewer with prev / next, counter and thumbnail strip, or the PDF frame). Anything else keeps "Open at source", and a `document` row also links to G-08 `?doc=<slug>`.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `spaces.catalogTab` | Catalog tab | show the {tab} catalog | `spaces.read` | `tab: enum:deliverables\|clients\|tools\|roles\|assets` |
| `spaces.openTemplate` | Open template | open the template of the deliverable {deliverable} | `spaces.read` | `deliverable: id` (Placeholder) |
| `spaces.openRoute` | Open hub page | open the hub page {code} | `spaces.read` | `code: string` |
| `spaces.selectSpace` | Open space | open the space {space} | `spaces.read` | `space: id` |
| `spaces.openProject` | Open project work | open the work of the project {project} | `spaces.read` | `project: id` |
| `spaces.previewAsset` | Preview an asset | preview the asset {asset} | `spaces.read` | `asset: id` |
| `spaces.closeAssetPreview` | Close the preview | close the asset preview | `spaces.read` | — |
| `spaces.openAssetSource` | Open an asset at its source | open the asset {asset} at its source | `spaces.read` | `asset: id` |

`spaces.previewAsset` and `spaces.closeAssetPreview` register while the page is mounted and were run through `window.__aluzina.actions.run` (verified: `spaces.previewAsset {asset:'ast-co-bombilla-aluzinogena'}` -> `{ ok: true, result: 'ast-co-bombilla-aluzinogena' }`, `spaces.closeAssetPreview` -> `{ ok: true, result: 'closed' }`). An asset with nothing to preview answers `'not previewable: this asset has no served render; its source link opens it'` instead of failing silently (D-047). The other three are declared, not registered - the tabs, the template links and the Work links are plain links and predate this card.
