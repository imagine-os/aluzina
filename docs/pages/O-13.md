# O-13 - Site reports

- route: `/#/ops/site-reports`
- surface: ops
- status: built
- spec: `apps/hub/src/modules/ops/specs.ts` (`siteReportsSpec`)
- model: Opus 5

## Purpose

ALUZINA site control of service E (stage 7): every visit to a site leaves a written record — date, progress, notes, decisions taken, problems found, who was responsible, and the date each problem must be resolved by. It is the page that makes G-08 true in the product.

## Layout (top to bottom)

1. `PageHeader` (O-13) with a "New site report" primary `Button` (only with `siteReports.write`) and the G-08 rule as a note.
2. Four `StatTile`s: visits recorded, latest progress, overdue resolutions, photographs on record.
3. `FilterBar`: project `Select`, count, Clear.
4. `EmptyState` when nothing matches, else one `Card` per report, newest first: a progress `StatTile` with a ten-block text bar, then notes, decisions, problems and the resolution date as a toned `Badge`, then the photograph links, a "no photographs on record yet" `Badge` when there are none, and the "Add photo" `Placeholder`.
5. `Modal` "New site report": project, date, progress, resolution date, notes, decisions, problems.
6. `Drawer`: the same record in full with its photographs.

## Data

Reads `siteReports` and `projects`. Creates `siteReports` rows.

## Rules

- **G-08** every site visit produces a written and photographic record. The written half is real; the photographic half is a link list today (see below).

## Logic

- Reports are listed newest first (`orderBy: 'date', dir: 'desc'`) and filtered by project. A `resolutionDue` in the past is flagged with a danger `Badge` and counted in the overdue tile.
- A new report records the person writing it as `responsibleId` and starts with no photographs; `progress` is clamped to 0-100 on write.
- Progress is rendered as a percentage plus a ten-block text bar (`████░░░░░░`) inside a `StatTile`, so it never depends on colour alone. The library has no meter / progress-bar atom yet — a `Meter` request is filed in the changelog draft; when it lands, the tile's hint becomes the meter.
- `photoUrls` are plain strings, rendered as external link buttons. Adding one is a `Placeholder` (`ops.addSitePhoto`), because there is no file-storage seam in the `DataProvider` yet. The action is registered so a call answers "not wired yet" instead of failing as `not-live`.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `ops.newSiteReport` | New site report | record the site visit of {project} on {date} | `siteReports.write` | `project: id`, `date: date`, `progress: number`, `notes`, `decisions`, `problems`, `resolutionDue: date` |
| `ops.openSiteReport` | Open site report | open the site report {report} | `siteReports.write` | `report: id` |
| `ops.filterSiteReportsProject` | Filter by project | show the site reports of {project} | `siteReports.write` | `project: id` |
| `ops.addSitePhoto` | Add a photograph | add a photograph to the site report {report} | `siteReports.write` | `report: id` |

All four register while mounted (verified: declared 4, none missing from the live list); `ops.addSitePhoto` answers with the "not wired yet" toast and message.

## Components

## Real vs mock / placeholder

Real: the report list, the project filter, the overdue flag, the progress reading and creating a report. `Placeholder`: "Add photo" — attaching a photograph needs file storage, which does not exist behind the provider yet. Editing an existing report is not offered yet (a visit record is written once); that is listed as an open question. Seed data: the three Noam visits, which carry empty `photoUrls`, so every card shows the "no photographs on record yet" badge — honest, and it is exactly the half of G-08 the product cannot keep yet.
