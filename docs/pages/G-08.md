## Purpose

## Logic

- **Served paths are relative** (`./brand/aluzina-portfolio.pdf`): Vite builds with `base: './'`, so the app keeps working under the GitHub Pages sub-path. The absolute URL for "open in a new tab" and "Share link" is `new URL(href, location.href)`.
- **The selected document is `?doc=`** (`portfolio` by default; an unknown value falls back to the portfolio), so `/#/brand/documents?doc=brochure` is a link that opens on the brochure and the back button works. Tabs and the View buttons both write it with `replace: true`.
- **The viewer is the shared `DocumentViewer`** (ar-17), the same organism S-13 and the company drawer use, fed by `viewerAssetOf(doc)` in `documents.ts`. Both marketing rows have `previewUrls: []`, so it takes its PDF branch, which is the same three levels the page's own `DocFrame` had: `<object type="application/pdf">` renders the PDF; its children render when the browser has no PDF plugin - an `<iframe>`, which most mobile browsers do show - and inside that a paragraph "Your browser cannot show PDFs here; download it instead." with the download link. That last fallback is also what a person sees when the file is missing from the server, so a broken deploy degrades to a readable sentence, never a blank rectangle. A document row that gains served page renders becomes the paged image viewer (prev / next, counter, thumbnail strip, arrow keys) with no page change. Heights did not move: `DocumentViewer.css` carries the same `clamp(22rem, 68vh, 56rem)`, raised to `clamp(30rem, 72vh, 76rem)` from 1920 up, that `.brand-doc__frame` had.
- **Every preview on the page is one component** (ar-17): the viewer Card, the company `Drawer` and every thumbnail are `DocumentViewer` / `Thumb` / `FileIcon` from the library. Nothing on G-08 hand-rolls an `<object>`, an `<iframe>` or an `<img>` any more.
- **View moves focus**: it selects the document, scrolls the viewer into view and focuses its container (`tabIndex={-1}`), so the keyboard path matches the visual one.
- **Share link** copies the absolute URL and confirms in a `Toast`; when `navigator.clipboard` is unavailable (insecure origin, old browser) the toast shows the URL instead of failing silently.
- **Download** is an `<a download>` wearing the `Button` classes: the library `Button` has no `download` attribute yet (requested), and a plain `href` would open the PDF instead of saving it. The action-bus handler creates the same anchor programmatically.
- Page count and size are recorded next to the file in `documents.ts` (portfolio 37 pages / 2.8 MB, brochure 19 pages / 3.0 MB) and must be edited in the commit that replaces a PDF. They render through `toLocaleString(lang)`, so Spanish reads `2,8 MB`.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `brand.viewDocument` | View a document | show the {doc} in the viewer | `brand.manage` | doc: enum:portfolio\|brochure |
| `brand.downloadDocument` | Download a document | download the {doc} as a PDF | `brand.manage` | doc: enum:portfolio\|brochure |
| `brand.openDocumentTab` | Open a document in a new tab | open the {doc} in a new tab | `brand.manage` | doc: enum:portfolio\|brochure |
| `brand.shareDocumentLink` | Copy the document link | copy the link to the {doc} | `brand.manage` | doc: enum:portfolio\|brochure |
| `brand.replaceDocument` | Replace a document | upload a new version of the {doc} | `brand.manage` | doc: enum:portfolio\|brochure |
| `brand.openCompanyDocument` | Open a company document | open the company document {asset} | `brand.manage` | asset: string |
| `brand.closeCompanyDocument` | Close the company document viewer | close the company document viewer | `brand.manage` | — |

ar-17 added **no action**: it swapped the components behind the existing controls, and the `DocumentViewer`'s own Download button under the viewer Card is the same intent as `brand.downloadDocument`.

The first four register while the page is mounted and were run through `window.__aluzina.actions.run` (verified: `brand.viewDocument {doc:'brochure'}` -> `{ ok: true, result: 'brochure' }`, tab switched, URL `?doc=brochure`, focus on the viewer). `brand.replaceDocument` is declared and deliberately not live: it is a `Placeholder`. `brand.openCompanyDocument` / `brand.closeCompanyDocument` (ar-15) are both live: they set the Drawer's open asset id, matching by asset id or by exact file name.

Nothing hover-only, nothing drag-only. Light and dark.

**Company documents (ar-15)**: re-verified at 390 and 1280 (Playwright, production preview build): 0 console errors, 12 tiles rendered, no horizontal overflow, the Drawer opens on click and the served page image returns HTTP 200. Each tile button (`brand-doc__company-tile`) is the whole thumbnail, one tab stop, `min-height: 2.75rem` well over the 44 px target; the Drawer keeps the library's own focus trap and Escape handling.
