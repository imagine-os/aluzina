# C-04 - Messages (client)

- route: `/#/client/messages`
- surface: client (PhoneShell)
- status: built
- spec: `apps/hub/src/modules/client/specs.ts` (`messagesSpec`)
- model: Opus 5

## Purpose

The official conversation with the studio, one thread per project (service 03 stage 01: the communication channel is agreed at onboarding). The client reads what the studio wrote, answers, and the whole history stays on the project.

## Screenshots

`docs/screenshots/C-04/en-390.jpg`, `en-1280.jpg`.

## Layout (top to bottom)

1. `PageHeader` (C-04).
2. `Card` titled with the project, carrying a "Mark as read" ghost action.
3. `Tabs`, one per project, when the client has more than one.
4. The thread: bubbles, mine on the right with the raised surface, the studio's on the left, each with author name, date and a "New" badge on what was unread when the page opened.
5. Composer: `Textarea` and a Send button.

## Data

Reads `projects` (scoped), `messages`. Writes `messages` (create) and `messages.readBy` (update).

## Rules

The project thread is the official channel (03 stage 01) and the counterpart of G-05: decisions are recorded, not scattered.

## Logic

- Messages are filtered to my project ids and ordered by `at`.
- **Send** creates a row with `authorId` = me, `at` = now, `readBy: [me]`. The list re-renders from the provider's subscribe event, so a second tab (or the studio portal) sees it without a reload (D-023, P-14).
- **Mark read** adds my id to `readBy` of every message of the shown thread I have not read, one update per row by id with `basedOn`. It runs automatically when the thread opens and on the explicit button; a ref of already-marked ids keeps the effect from writing the same row twice.
- The "New" badge is captured once, on first load, so marking read does not make it flicker away while the person is reading.
- Without `messages.write` the thread is read only and the composer, the button and both write actions are absent.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `client.sendMessage` | Send a message | send the message {body} to the studio about {project} | `messages.write` | `project: id`, `body: string` |
| `client.markRead` | Mark as read | mark the conversation about {project} as read | `messages.write` | `project: id` |
| `client.selectProject` | Select project | open the thread of {project} | `own.projects.read` | `project: id` |

## Components

`PageHeader`, `Card`, `Tabs`, `Textarea`, `Button`, `Badge`, `EmptyState`, `Skeleton`. The bubble is local markup over tokens (requested for the library: `MessageBubble` / `Thread`).

## Real vs mock / placeholder

All real, no `Placeholder`. Verified: the ten seeded Casa Laureles messages render, the unread one from Miguel carries "New", sending adds an eleventh bubble and the row is written through the provider.

## Responsive and input check (P-01, P-03)

Verified at 360 / 390 / 768 / 1280 / 1920, light and dark. Bubbles cap at 26 rem so a long line stays readable on a TV; the composer and Send are 44 px; `Tabs` are the library's arrow-key tablist.
