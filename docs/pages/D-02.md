# D-02 - Component library

- route: `/#/dev/components`
- surface: dev
- status: built
- spec: `apps/hub/src/modules/dev/specs.ts` (`componentsSpec`)
- model: Fable 5.1

## Purpose

Shows every library component from its `.meta.ts` with a live example, props, accessibility notes, usages and folder path, so module workers, Justin and the owner see the design system in the product (P-07, D-017). If a component is not here, pages do not use it.

## Screenshots

`docs/screenshots/D-02/en-390.jpg`, `en-1280.jpg` (live, after the 0006 deploy).

## Layout (top to bottom)

1. DesktopShell: top bar (Dev tools · Developer badge, EN/ES, theme, dev mode, Back to hub, avatar / user menu), sidebar "Developer": Components, Page specs.
2. `PageHeader`: breadcrumb Dev tools / Component library, h1 (+ `D-02` chip in dev mode), subtitle with the component count.
3. `FilterBar`: `SearchField` (name, purpose, usages), summary "n of 31", Clear.
4. `Tabs`: All / Atoms / Molecules / Organisms / Templates with counts.
5. One `Card` per component: name, purpose, tier badge (+ "No example" badge when missing), example stage (`data-example`), props `KeyValue`, a11y list, usages, `src/components/...` path.

## Data

None (reads `src/design/library.ts`, a glob over `*.meta.ts` and `*.example.tsx`).

## Rules

None.

## Logic

- Search is case-insensitive over name, purpose and usages; tabs filter by tier; Clear resets both.
- Examples are real components with local state (Kanban moves, Modal / Drawer open, Toast fires).
- Guarded by `dev.tools` (dev and founder); other roles get the RequireRole page with "Switch to Developer / Founder".

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `dev.searchComponents` | Search components | find the component {query} | `dev.tools` | `query: string` |
| `dev.filterTier` | Filter by tier | show only {tier} components | `dev.tools` | `tier: enum:all\|atom\|molecule\|organism\|template` |
