# D-07 - Canvas

- route: `/#/dev/canvas`
- surface: dev
- status: built
- spec: `apps/hub/src/modules/tools/specs.ts` (`canvasSpec`)
- model: Opus 5

## Purpose

Every registered page of the hub laid out as a zoomable card grid grouped by surface, with its deploy-time thumbnail, code, status, shell and permission. It is the "see the whole system at once" view the Hub deliverable asks for (P-12): zoom out to read the shape of the product, activate a card to land on that page as a demo user of its surface.

## Layout (top to bottom)

1. DesktopShell (dev surface).
2. `PageHeader`: breadcrumb, h1, subtitle.
3. Four `StatTile`s: pages, built, stubs, surfaces.
4. `FilterBar`: `SearchField` (code, name, path, purpose), surface `Select`, status `Select`, summary, Clear.
5. Zoom toolbar: − / + `Button`s, the current percentage (`aria-live`), a Fit `Button`, a preset `Select` (25 / 50 / 75 / 100 / 150 / 200 %) and the hint line.
6. Scrolling canvas stage: one `<section>` per surface in the SURFACES order, each a grid of `SurfaceCard`s (thumbnail, code, status, page name, `#path · shell · permission`, "Open").
7. `EmptyState` with a Clear button when nothing matches.

## Data

None. Routes come from `RoutesContext` (the same manifest as `window.__aluzina.routes`); the session comes from `useSession`.

## Rules

D-015 (identity is mocked, role guards are real): a card never bypasses a guard — it switches the session to the demo user of that surface first, exactly like the hub cards.

## Logic

- Built / Stub comes straight from `route.status`, so a card can never disagree with the manifest.
- The thumbnail is `./thumbs/<code>.jpg?v=<build id>` (D-011); `SurfaceCard` falls back to its bilingual "no preview yet" tile when the file is missing, which is what every new code shows until `scripts/thumbnails.mjs` gains a target for it.
- Zoom is the `--canvas-zoom` custom property: the grid is laid out at `width: calc(100% / zoom)` and `transform: scale(zoom)` from the top left, so the stage never scrolls sideways — the columns reflow instead. The buttons step through the presets, the Select jumps to one, Ctrl + wheel is an extra (a non-passive listener so it does not also zoom the browser). Never wheel-only (P-03).
- Fit measures the rendered grid height against the stage and snaps down to the preset that shows all of it; pressing it again converges.
- Activating a card navigates to the page, switching the session to the demo user of that surface first when the current role lacks the route permission, with a toast naming the role.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `tools.zoomCanvas` | Zoom the canvas | zoom the canvas to {zoom} percent | `dev.tools` | `zoom: number` |
| `tools.fitCanvas` | Fit the canvas | fit the whole canvas in view | `dev.tools` | — |
| `tools.filterCanvasSurface` | Filter the canvas by surface | show only the {surface} pages | `dev.tools` | `surface: enum:all\|hub\|founder\|ops\|studio\|brand\|client\|dev\|docs\|manual\|public` |
| `tools.filterCanvasStatus` | Filter the canvas by status | show only {status} pages | `dev.tools` | `status: enum:all\|built\|stub` |
| `tools.searchCanvas` | Search the canvas | find the page {query} | `dev.tools` | `query: string` |
| `tools.openCanvasPage` | Open a page from the canvas | open the page {code} | `dev.tools` | `code: string` |

All six register while mounted; `tools.zoomCanvas` and `tools.fitCanvas` were run through `window.__aluzina.actions.run`.

## Components

`PageHeader`, `StatTile`, `FilterBar`, `SearchField`, `Select`, `Button`, `SurfaceCard`, `EmptyState`.

## Real vs mock / placeholder

All real: the cards are the live route manifest and every one of them opens. No Placeholder on this page. Thumbnails are real where the deploy captured them and the bilingual "no preview yet" tile everywhere else.

## Responsive and input check (P-01, P-03)

Verified at 360, 390, 768, 1280 and 1920 (`spec.checkedAt`), plus a 2560 overflow check: no horizontal page scroll at any width, light and dark. The zoom toolbar wraps; every control is a 44 px target; the percentage is announced with `aria-live`; cards are one focusable element each (`SurfaceCard`), so Tab walks the canvas in reading order. Nothing hover-only, nothing drag-only.

## Strings (P-13)

Namespace `tools.canvas.*` + `tools.surface.*` + `core.*`. EN complete, ES complete.

## Open questions

- A `ZoomStage` component (scroll frame + `--canvas-zoom` + fit maths) belongs in the library: the simulator and any future whiteboard want the same thing.
- Should the canvas offer a free-position mode (drag cards into a layout saved per person) later, or stay a grouped grid? A grid needs no drag, which is why it is the first pass (P-03).
