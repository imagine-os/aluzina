# D-04 - Multiuser

- route: `/#/dev/multiuser`
- surface: dev
- status: built
- spec: `apps/hub/src/modules/dev/specs.ts` (`multiuserSpec`)
- model: Fable 5.1

## Purpose

QA aid for the realtime seam (D-023, D-024): how to open two tabs as two demo users, who is present right now, and the last 20 `activity` rows the provider wrote.

## Screenshots

`docs/screenshots/D-04/en-1280.jpg` (live, as dev).

## Layout (top to bottom)

1. `PageHeader` (D-04).
2. `Card` "How to test it": three steps, "Open a tab as <role>" buttons (founder, ops, studio, brand; new tab with `?as=<role>` before the hash), "Reset demo data" (danger), `KeyValue` with the channel names (`aluzina-data`, `aluzina-presence`), heartbeat / expiry (5 s / 15 s) and this tab's id.
3. `Card` "Who is here": `PresenceBar` + `DataTable` (person, route, tabs, last seen).
4. `Card` "Last 20 activity rows": `DataTable` (when, who, row, field, from -> to).

## Data

Reads `activity` (last 20 by `at`), `tasks` (titles). Writes: `reset()` (re-seeds every entity in every tab).

## Rules

None.

## Logic

Presence from `usePresence()`; the `?as=` user is kept per tab in `sessionStorage` (`aluzina.tabUser`) so each tab stays its person across reloads. Reset propagates through the data channel.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `dev.openAs` | Open a tab as a role | open a new tab as {role} | `dev.tools` | `role: enum:founder\|ops\|studio\|brand` |
| `dev.resetData` | Reset demo data | reset the demo data to the seeds | `dev.tools` | – |
