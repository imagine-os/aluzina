# D-13 - Textures and effects

- route: `/#/design/effects`
- surface: design
- status: built
- spec: `apps/hub/src/modules/design/specs.ts` (`effectsSpec`)
- model: Opus 5 (0014), silver values 0015 (Fable 5.1)

## Purpose

The playground for the two brand finishes and the rule that governs them. It shows the `Shimmer` shader (brushed metal and thin-film iridescence) at every intensity with motion on or off, the CSS gradient it degrades to, the four texture tiles at four sizes, the sheen sweep and gradient text — so a builder can see exactly what a finish costs and where it is allowed before putting one in a page.

`docs/screenshots/D-13/en-390.jpg`, `en-1280.jpg`, `en-1920.jpg` (light) and `en-390-dark.jpg`, `en-1280-dark.jpg` (dark), from the local 0.9.0 preview as dev (silver edition, changelog 0015) + `routes.json`. ## Layout (top to bottom)

1. `PageHeader` (breadcrumb Design system / Textures and effects).
2. **Controls**: intensity select (0.2 … 1), motion toggle, a `prefers-reduced-motion` badge when the system asks for it.
3. **Shimmer**: a metal band with the iridescent wordmark, an iridescent band, two square tiles, two pill chips, and the two CSS fallbacks side by side.
4. **Texture tiles**: the four patterns with a tile-size select.
5. **CSS finishes**: the sheen band (the toggle lives on the band, so focusing it demonstrates `:focus-within`), `.text-metal` and `.text-iridescent` headings.
6. **Where each one is allowed**: the six rules.

## Logic

- Intensity and motion are page state passed to the `Shimmer` atom. Motion initialises from `matchMedia('(prefers-reduced-motion: reduce)')` and follows a change of that setting.
- The tile-size select sets `--texture-size` on the tile grid in rem, so patterns keep scaling with `--scale`.
- The sheen toggle adds `.sheen`; the sweep itself only runs on hover / focus-within and never under reduced motion.
- Every surface on the page is decorative and `aria-hidden`; overlaid text is `--brand-ink` (a two-class rule beats `.eyebrow`'s muted colour).

## Components

## Real vs mock / placeholder

All real, no placeholders. The shader is a real WebGL2 canvas; in a container without a GPU Chromium runs it in software and it still renders, and where WebGL2 is missing entirely the CSS gradient shows instead (the page shows that fallback next to the live one).

## Responsive and input check (P-01, P-03)

Verified at 390, 1280, 1920 in both themes (`checkedAt`); no horizontal overflow, no console errors. Controls are native `select` and `button` (keyboard, touch, pen, d-pad and voice without extra code), all >= 44 px. The shader tracks pointer, pen and touch, and device tilt where the browser reports it; none of that is required to use the page.
