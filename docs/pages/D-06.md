## Purpose

The repo's `docs/` tree inside the product (build plan step 5, P-11): the start-here map, the binding principles, the build plan, the decisions, the changelog, the verbatim prompts, the page docs, the knowledge base, the reference and QA notes, the machine-readable plan and the source archives — all read from the same files an agent reads, so the studio's memory and the product's memory can never be two different things. Guarded by `docs.read` (every role except the client).

## Layout (top to bottom)

1. `PageHeader`: "Documentation", subtitle, **Open on GitHub** (the current document, new tab).
2. Left column (>= 1024 px, otherwise a `Drawer` behind "Browse documents"): a `SearchField`, the match / document count, the `SpaceTree` of `docs/`, the search-scope hint and **Load every document**.
3. Right column: the document path (`docs/<path>`), then the document — the `Markdown` atom for a `.md` file, the plan table for `plan/plan.json`, a `Skeleton` while the chunk loads, an `EmptyState` for an unknown path.

## Data

No entities. Documents come from `import.meta.glob('@docs/**/*.md', { query: '?raw', import: 'default', eager: false })` through the `@docs` alias (D-037); `docs/plan/plan.json` comes from the typed `src/plan` module.

## Rules

None. P-11 (the docs tree is the memory) and P-13 (the chrome is bilingual, the documents are shown as written) are the principles this page serves.

## Logic

- **Lazy by file**: each document is its own chunk, so opening the viewer costs the shell, not 800 KB of Markdown. An opened document is cached in component state, which is also what the full-text search reads.
- **Tree order**: root files in reading order (README, platform-principles, project-brief, build-plan, kanban, decisions), then `changelog/`, `prompts/`, `pages/`, `knowledge/`, `reference/`, `qa/`, `plan/`, `source/`, each nested by path segment. Folder nodes carry a count; the folders of the open document are expanded automatically. `SpaceTree` gives the whole thing the ARIA tree pattern (one tab stop, arrows, Home / End, type-ahead).
- **Search** always matches paths and file names and, for every document already loaded, its text; the tree is rebuilt from the matches so the results keep their folders. **Load every document** fetches the rest for a full-text search.
- **Relative links** between documents are rewritten before rendering to this viewer's own absolute URL (the `Markdown` atom only linkifies http(s) and mailto), and a delegated click handler turns the click into an in-app navigation instead of a new tab. Links that leave `docs/` are left exactly as written.
- `plan/plan.json` renders as a sortable `DataTable` (task, title, step, status pill, model, codes, dependencies), not as raw JSON.

## Components

`PageHeader`, `SearchField`, `SpaceTree`, `Markdown`, `DataTable`, `StatusPill`, `Badge`, `Button`, `Drawer`, `EmptyState`, `Skeleton`.

## Real vs mock / placeholder

Everything is real: real files, real search, real GitHub links (`https://github.com/imagine-os/aluzina/blob/main/docs/<path>`). No `Placeholder`. Not built: anchor links inside a document (the `Markdown` atom has no heading ids), a table of contents per document, and editing a document from the app.

## Responsive and input check (P-01, P-03)

Verified with Playwright at 360 / 390 / 768 / 1280 / 1920 / 2560 / 3840 (`spec.checkedAt`), light and dark, EN and ES: no horizontal page overflow, no console errors. Under 1024 px the tree moves into a left `Drawer` (focus trapped, Escape closes) behind a 44 px button. Long paths and code spans wrap (`overflow-wrap: anywhere`) so a phone never scrolls sideways; the reading measure is capped at 80ch and grows one step at 2560+.

## Strings (P-13)

`docs.*`; EN and ES complete, including the folder descriptions and the plan statuses. The documents themselves are shown as written (they are English today).
