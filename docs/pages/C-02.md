# C-02 - Project detail (client)

- route: `/#/client/projects/:projectId`
- surface: client (PhoneShell)
- status: built
- spec: `apps/hub/src/modules/client/specs.ts` (`projectSpec`)
- model: Opus 5

## Purpose

Everything the client may see about one project: the service they bought and what it promises, the playbook phases with the studio's ticks as read-only progress, the documents finalised for them, the dates, who leads the design, and the way into the revision matrix when the scheme is with them. Not in the menu; it is opened from the project card on C-01.

## Layout (top to bottom)

1. `PageHeader` (C-02) with the breadcrumb back to C-01 and a primary "Message the studio".
2. `Card` with the service name, its outcome, the pipeline `StatusPill`, the current phase `Badge` and the progress bar.
3. Raised `Card` (only while `pipelineStatus === 'client-review'`) — "Your review is needed" with a button to C-03.
4. `Card` "What we do, step by step": one `<details>` disclosure per phase, the current one open, a done/total badge per phase and the items as read-only ticks.
5. `Card` "Documents for you": the project's finalised documents with status pill and date.
6. `Card` "Dates" (`KeyValue`: start, estimated delivery, service started) and `Card` "Your studio team" (`Avatar` + lead designer).
7. The "Not your project?" note.

## Data

Reads `projects` (scoped), `engagements`, `documents`. Writes nothing.

## Rules

G-03 (the studio owns the checklist), G-05 / stage 10 (comments belong in the revision matrix — the banner points there), the playbook phase model (`SERVICES`, `phaseItems`, `checkKey`).

## Logic

- A `projectId` that is not linked to this client renders an `EmptyState` with a way back; another client's project is never rendered, whatever the URL says.
- Phases come from `serviceByCode(project.serviceCode)`; ticks from `engagements.checks[checkKey(phase.id, index)]`. Read only: the client never writes a check.
- Documents are filtered to `final`, `sent` and `signed`, so a draft the studio is still writing never reaches the client. There is no `documents.clientVisible` field yet — requested.
- The client-review banner is derived from `projects.pipelineStatus`, so it disappears the moment the studio moves the project on.

## Components

## Responsive and input check (P-01, P-03)

Verified at 360 / 390 / 768 / 1280 / 1920, light and dark. Every `<summary>` is a 44 px target that opens with Enter or Space and shows the focus ring; the tick list is text plus a glyph with a visually hidden "Done" / "Pending", never colour alone.

## Strings (P-13)

Namespace `client.project.*` (plus `client.common.*`, `core.status.*`). EN complete, ES complete.

## Open questions

- Deliverables should be their own thing (a `deliverables` row or `documents.clientVisible`), not a status filter over `documents`.
- The team card shows only the lead designer; the founder is the client's real counterpart in the seeded thread, so a "your contacts" list may be truer.
