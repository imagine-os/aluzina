# O-03 - Pending tasks

- route: `/#/ops/tasks`
- surface: ops
- status: built
- spec: `apps/hub/src/modules/ops/specs.ts` (`tasksSpec`)
- model: Opus 5

## Purpose

"Tracking pending tasks": the whole studio's task board by state, filtered to a project, a role or Miguel's own list. Moving a card is a real write, so the board is the system of record rather than a picture of it.

## Screenshots

`docs/screenshots/O-03/en-390.jpg`, `en-1280.jpg` — captured by the integrator; working captures taken at five widths.

## Layout (top to bottom)

1. `PageHeader` (O-03) with a `Placeholder` "New task" button.
2. `FilterBar`: search, project select, team role select, "Only mine (Miguel)" checkbox, count summary, clear.
3. `Kanban` with four columns: to do | doing | blocked (warning) | done (success). Each card shows the project, the days-left line and the assignee.
4. `Drawer` with the task detail: project, assignee, owner role, priority, due date, what it waits for, and "Mark done".

## Data

Reads `tasks`, `projects`. Writes `tasks.status`.

## Rules

None numbered yet.

## Logic

- The Kanban move buttons call `data.update('tasks', id, { status })` with the target column id; there is no drag, so keyboard, touch, pen and a future d-pad all work (P-03).
- Filters are page state; "only mine" compares `assigneeId` with the signed-in demo user, never the role string.
- `dependsOn` ids are resolved to task titles in the drawer.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `ops.moveTask` | Move task | move the task {task} to {status} | `tasks.manage` | `task: id`, `status: enum:todo\|doing\|blocked\|done` |
| `ops.completeTask` | Mark task done | mark the task {task} as done | `tasks.manage` | `task: id` |
| `ops.viewTask` | Open task | show the task {task} | `tasks.manage` | `task: id` |
| `ops.newTask` | New task | create a task called {title} | `tasks.manage` | `title: string` |

## Components

`PageHeader`, `FilterBar`, `SearchField`, `Select`, `Checkbox`, `Kanban`, `Drawer`, `KeyValue`, `StatusPill`, `Button`, `Placeholder`.

## Real vs mock / placeholder

Moving, opening and completing are real writes. `Placeholder`: "New task".

## Responsive and input check (P-01, P-03)

Checked at 360 / 390 / 768 / 1280 / 1920, light and dark. The board scrolls inside itself (the page never scrolls sideways); filters stack on phones. Move buttons are 44 px icon buttons with an accessible name naming the card and the target column.
