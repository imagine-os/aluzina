# O-02 - Project schedule

- route: `/#/ops/schedule`
- surface: ops
- status: built
- spec: `apps/hub/src/modules/ops/specs.ts` (`scheduleSpec`)
- model: Opus 5

## Purpose

"The overall project schedule" in Miguel's roster, in two views of the same commitments: a timeline of every task with its dependencies, and a month calendar that merges meetings, expected deliveries and payment due dates so nothing lands on a day nobody looked at.

## Screenshots

`docs/screenshots/O-02/en-390.jpg`, `en-1280.jpg` — captured by the integrator; working captures taken at five widths against the dev server.

## Layout (top to bottom)

1. `PageHeader` (O-02) with a `Placeholder` "Schedule a meeting" button.
2. `Tabs`: Timeline (count of dated tasks) | Calendar (count of events in the shown month).
3. Timeline tab: an explanatory line, then `Timeline` with one bar per dated task.
4. Calendar tab: a legend line, then `Calendar` with the merged events.
5. `Drawer` with the detail of the bar or event that was activated.

## Data

Reads `tasks`, `meetings`, `deliveries`, `payments`, `projects`, `suppliers`. Writes nothing (the owning pages do).

## Rules

None numbered yet.

## Logic

- A bar runs from the later of the task's `created_at` and the latest `dueDate` among its `dependsOn` tasks, to its own `dueDate`; tasks without a due date are left out, and a start later than the end is clamped. The schema has no task start date, so this is a derivation, stated on the page.
- Bar tone: done = success, blocked = warning, urgent priority = danger, otherwise accent.
- Calendar events: meetings at `startsAt`, deliveries at `confirmedDate ?? expectedDate`, payments at `dueDate` (paid = success, overdue = danger, otherwise warning). The month is page state, starting on the current month.
- The drawer is one component for all four row kinds; it builds a `KeyValue` list per kind.
