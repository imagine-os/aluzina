# G-06 - Graphic revisions queue

- route: `/#/brand/revisions`
- surface: brand
- status: built
- spec: `apps/hub/src/modules/brand/specs.ts` (`revisionsSpec`)
- model: Opus 5

## Purpose

"Graphic revisions" from Angélica's roster: everything the rest of the studio asks her to revise - layouts, PDFs, decks, social pieces, images - as one board she works down.

## Screenshots

Check captures: `shots/brand/G-06-en-390.png`, `G-06-en-1280.png`, `G-06-after-move-1280.png`. Repo set: integrator pass.

## Layout (top to bottom)

1. `PageHeader` with "Request a revision" (`Placeholder`).
2. Five `StatTile`s: one per column plus overdue.
3. `FilterBar`: search + kind.
4. `Kanban`: requested | in progress | delivered | approved.
5. `Drawer`: revision detail (`KeyValue`).

## Data

Reads `revisions` and `projects`; writes `revisions.status` on every move.

## Rules

P-01, P-03 (nothing drag-only), P-05, P-09, P-13.

## Logic

- Moving a card writes the status through `useData().update` and toasts the new column; the board re-renders from the provider's subscribe event (verified).
- The card subtitle is "project - requester", resolved through `demoUserById`.
- Overdue = due date past and status neither delivered nor approved.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `brand.moveRevision` | Move revision | move the revision {revision} to {status} | `revisions.manage` | revision: id, status: enum |
| `brand.openRevision` | Open revision | open the revision {revision} | `revisions.manage` | revision: id |
| `brand.requestRevision` | Request a revision | request a {kind} revision for {project} | `revisions.manage` | kind: enum, project: id |

## Components

`PageHeader`, `StatTile`, `FilterBar`, `SearchField`, `Select`, `Kanban`, `Drawer`, `KeyValue`, `StatusPill`, `Button`, `Placeholder`.

## Real vs mock / placeholder

Real: the board, the moves, the filters. `Placeholder`: "Request a revision" (no create form yet). Note that the requester today is another demo user; when the studio files its own requests this becomes a cross-portal flow.

## Responsive and input check (P-01, P-03)

Verified at 360 / 390 / 768 / 1280 / 1920, light and dark, EN and ES. The board's move buttons are real buttons with `aria-label`s, so keyboard, touch, pen and a future d-pad all work; there is no drag. No target under 44 px.

## Strings (P-13)

Namespace `brand.revisions.*` plus shared `brand.*`. EN complete, ES complete.
