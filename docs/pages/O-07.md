# O-07 - Payments and accounts

- route: `/#/ops/payments`
- surface: ops
- status: built

## Purpose

"Managing payments, accounts" and "keeping track of who owes what, deadlines, and current status": money clients owe the studio and money the studio owes suppliers on one page, with what is overdue today pulled to the top and the settling done in place.

## Layout (top to bottom)

1. `PageHeader` (O-07).
2. Four `StatTile`s: clients owe us, we owe suppliers, overdue (amount, count as hint), net balance.
3. Card "Overdue right now": the same table filtered to overdue rows, empty state "Nothing overdue".
4. `FilterBar`: search (counterparty, concept), direction select, status select, count, clear.
5. `DataTable` of every payment: who, concept, project, direction, amount, outstanding, due (with days), status; row actions Mark paid / Register part payment.
6. `Modal` "Register a part payment" with an amount field.

## Data

Reads `payments`, `projects`. Writes `payments.paidCop`, `paidDate`, `status`.

## Rules

None numbered yet.

## Logic

- Outstanding is `amountCop - paidCop`, never negative; the tiles sum it by direction over rows that are not paid, and the net balance is in minus out.
- A row whose `dueDate` has passed and is not paid is shown as overdue even when the stored status still says `due`, so the page never contradicts the calendar.
- Mark paid writes `paidCop = amountCop`, `paidDate = today`, `status = 'paid'`.
- A part payment adds to `paidCop`, sets `partial`, or `paid` with today's date when it covers the balance.
