## Purpose

The same spaces, posts and relations as one picture, now in the five views Justin asked for (prompt 0012, rebuilt on the imagine-os graph gallery): **3D objects** (his favourite, the default), **Lanes skill tree**, **Radial tree**, **Objects map** and the dependency-free **Force 2D** that is also the fallback when a device cannot draw 3D. Nodes are never bare dots: they carry the system's own pictures - a person's initials, a page's deploy-time thumbnail, a space, post or catalog glyph.

## Layout (top to bottom)

1. `PageHeader`.
2. `Tabs`: 3D objects (default), Lanes skill tree, Radial tree, Objects map, Force 2D. The choice is remembered in `localStorage` under `aluzina.graphView`.
3. Controls: focus `Select` (every space and post), depth `Select` (1 / 2 / 3 hops, everything), camera `Button`s − / + / Fit / Reset view (+ an auto-rotate `ToggleButton` in 3D), "Show archived" and "Show all nodes" `Checkbox`es.
4. Kind `ToggleButton`s (area, topic, role, client, deliverable, tool, project, archive, post, other entities) with the legend dot.
5. A notice line when the 3D view falls back (no WebGL, or reduced motion with a "Show 3D anyway" button) and when the node cap trimmed the picture.
6. The chosen view in its own region (`GraphViews`, or `RelationGraph` for Force 2D). The 3D view is `React.lazy` behind a `Skeleton`.
7. Legend: node and link counts, link styles, what the pictures mean, and the gallery credit.

## Data

Reads `spaces`, `posts`, `filings`, `relations` and the entity index tables (labels and routes for relation targets); `deliverables` and `tools` also supply the page code behind a node. No writes. The graph model (`buildGraph`) is unchanged.

## Logic

- Nodes: spaces (tone by kind, areas larger), posts, and any entity a relation points at. Edges: `child` (tree), `filed` (dashed accent), relation kinds (arrow).
- Kind filters apply first, then a breadth-first cut `depth` hops around the focus; when the focus itself is filtered out, its direct neighbours are kept.
- **Pictures from the system** (`graphImages.ts`): people and roles show the demo user's initials; a node that opens a hub page (a deliverable whose `templateDocKind` is a page code, a tool whose `replacedByModule` is a code or a route path) shows `./thumbs/<code>.jpg?v=<build>` with the hub's own fallback tile until that thumbnail exists; spaces show their `glyph`, posts a glyph per kind, catalog entries the glyph of the space about them. In 3D the same picture becomes a canvas texture on a sprite with the label underneath.
- **Views** (`components/organism/GraphViews/`, all deterministic): *Lanes* = one swimlane per area or entity kind (the six biggest, the rest packed into "Other entities"), columns by hop distance, nodes wrapped into sub-columns, curved links. *Radial* = focus at the centre, one ring per hop, each node placed near its parents' angle. *Objects map* = image tiles packed into one framed cluster per lane. *3D objects* = ground grid, depth bands per kind, a short relaxation (springs + repulsion + band pull), a primitive body per kind, the picture and label as sprites, curved line edges.
- **Performance**: depth stays 2 by default and only the 140 nodes closest to the focus are drawn until "Show all" is on; the 3D chunk (549.65 kB raw / 139.28 kB gzip) loads only when the 3D tab is opened; the render loop runs only while something moves and never while the tab is hidden; every geometry, material and texture is disposed on unmount.
- **Fallback**: no WebGL -> Force 2D with a notice; `prefers-reduced-motion` -> Force 2D with a notice and a "Show 3D anyway" button, and the 3D view then never auto-rotates or tweens.
- **Camera / viewport**: − / + / Fit / Reset are buttons on the page driving the view's imperative handle; drag and pinch are extras, there is no wheel zoom and no scroll-jacking. Fit never zooms below 38 % (labels stop being readable); when the drawing cannot fit at that scale it starts on the focus node, and the viewport is clamped inside the drawing so panning never wanders into empty space.

## Keyboard, touch and focus (P-03, P-04)

- The drawing is paint only. One overlay (`NodeLayer`) carries every tab stop and tap target, so 3D and 2D behave identically.
- Roving tabindex: the graph is one tab stop. Arrows walk the highlighted node's neighbours (list order when it has none), Enter opens it (space -> K-02, post -> K-03, anything else -> its route or a toast), Space re-centres the query on it (`?focus=`), Home returns to the focus node.
- The camera / viewport follows the highlighted node; the focus node draws a ring in the scene, the overlay button draws the global focus ring.
- Hover is never alone: the same card (label, type, hops, link count) shows on focus. On touch the first tap selects and centres, the second opens. Targets are 44 px at 1280 and grow with `--scale` (50 px at 1920, 66 px at 2560, 88 px at 3840).

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `spaces.switchGraphView` | Switch graph view | show the graph as {view} | `spaces.read` | `view: enum:objects3d\|lanes\|radial\|map\|force2d` |
| `spaces.autoRotate` | Auto-rotate | start or stop turning the 3D graph | `spaces.read` | – |

| `spaces.focusGraph` | Focus node | centre the graph on {node} | `spaces.read` | `node: string` |

| `spaces.filterGraphKind` | Toggle kind | show or hide {kind} nodes in the graph | `spaces.read` | `kind: enum` |
| `spaces.zoom` | Zoom | zoom the graph {direction} | `spaces.read` | `direction: enum:in\|out\|fit` |

| `spaces.showArchived` | Show archived | show or hide archived spaces | `spaces.read` | – |

All ten are registered with `useRegisterActions` while the page is mounted (D-036), so `/#/dev/actions`, WebMCP and the voice controller can run them.

## Components

`PageHeader`, `Tabs`, `Select`, `ToggleButton`, `Checkbox`, `Button`, `Skeleton`, `GraphViews` (new organism), `RelationGraph` (2D fallback), `Badge`, `EmptyState`.

## Real vs mock / placeholder

Real over the seeded rows; no `Placeholder`. Page thumbnails are real when a deploy has run `npm run thumbs`; in dev and before the first deploy every thumbnail node shows the bilingual "no preview yet" tile with its page code, which is the same behaviour as the hub cards. Not built: label collision avoidance, saving a view, 3D picking by clicking the object itself (the overlay button over it is what you click), glTF object models (the gallery's `.glb` bodies are replaced by three primitives).
