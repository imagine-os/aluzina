## Purpose

The Asana views the team already uses, inside the OS: every task of the studio as a **List**, **Board**, **Timeline** or **Calendar**, live for everyone, with the default each role expects (prompt 0004). Miguel plans and chases from the Timeline, Sarai works her Board, Alejandra reads the approvals list grouped by project, Angélica sees her own tasks.

## Layout (top to bottom)

1. `PageHeader` (W-01) with an "Open a project…" `Select` that jumps to W-02 and, for founder and ops, a primary "New project from template" button to W-03 (0020).
2. `WorkHeader`: view tabs with counts, `PresenceBar`, "Add task"; search, Filters (panel: assignee, status, priority, due window, tag, project, **deliverable**, show completed), Sort, Group by, saved views select + Save view + delete.
3. One of `WorkList`, `WorkBoard`, `WorkTimeline` (zoom Day / Week / Month, Go to today), `WorkCalendar`.
4. `TaskDetailDrawer` for the open task.

## Data

Reads `tasks`, `sections`, `projects`, `comments`, `activity`, `deliverables` (the catalog, for the badges, the drawer `Select` and the filter). Writes `tasks` (every field, including `deliverableId` and `parentTaskId`), `comments` (create); the provider writes `activity`.

## Rules

None numbered; permissions `tasks.manage` (ops, founder: everything) and `tasks.own.write` (studio, brand: tasks assigned to me or created by me), read for all four.

## Logic

- One `ViewState` (view, filters, sort, groupBy); the last state per scope and named saved views persist per user in `aluzina.views.<userId>` (D-025). Role default when nothing is saved: founder List by project with tag `aprobación` and completed hidden; ops Timeline by section sorted by due date; studio Board by status sorted by priority; brand List filtered to `u-angelica`.
- Writes carry `basedOn = task.updated_at`; a newer stored row still wins last-write and toasts the other writer (D-024). Other tabs get the change over `BroadcastChannel('aluzina-data')` and re-render (D-023).
- Board moves write the target group's field: section -> `sectionId`; status -> `status` (+ `completedAt`); assignee -> `assigneeId`; project -> `projectId` (+ `sectionId` null); due -> `dueDate` (today / +7 / +30 / +45 / none); "overdue" refuses with a toast.
- Timeline: tasks with a start or due date; due-only tasks are milestones; dependency arrows from `dependsOn`; the chart scrolls inside its container and opens on today.
- **Nesting (0020, D-062)**: `parentTaskId` is the real tree (`subtasks[]` stays the checklist). The List indents children under their parent with a 44 px twisty per parent (`aria-expanded`, Enter / Space collapses the subtree); the Board and the Timeline show top-level tasks only, each naming its child count (`↳ n`), and the view tabs count what each view shows. An empty imported title renders as "(untitled task)".
- **Deliverables (0020)**: a task with `deliverableId` carries a green `▣ <name>` badge in the List and on the Board card; the drawer has a Deliverable `Select` over the catalog; the Filters panel has a Deliverable filter including "No deliverable".
- **Imported rows (0020)**: `externalId` shows in the drawer as a read-only "Imported from Asana · asana:…" line; the tag `asana` is on every imported task.
- Keyboard on a list row: arrows move, Enter opens, Space toggles complete, Shift+Space selects, Shift+arrows extend, Escape clears; on timeline bars: arrows / Home / End move, Enter opens; Drawer: Escape closes, focus returns.

## Real vs mock / placeholder

Everything on the page writes real rows through the DataProvider (mock, localStorage, cross-tab). No `Placeholder`. Not built: pointer drag (bonus), section create / rename UI, a `views` table, registration of the 31 pre-0020 `work.*` actions.

## Responsive and input check (P-01, P-03)

Smoke at 360 / 390 / 768 / 1280 / 1920 / 2560 for all four views: no console errors, `scrollWidth === clientWidth` (board and timeline scroll inside themselves). List rows become cards under 1024 px (the sidebar leaves ~28rem between 768 and 1023); the priority column folds into the title line between 1024 and 1439. Every control is a library `Button` / `Select` / `Input` / `Checkbox` >= 44 px; nothing hover-only or drag-only; timeline bars keep a 44 px target around milestones and short bars; the rem-based zoom scales with the `--scale` bands at 2560+.
