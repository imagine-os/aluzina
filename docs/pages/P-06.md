# P-06 - Example set

- route: `/#/sets?p=<projectId>,<projectId>&t=<title>&lang=es|en&print=1`
- surface: public (`bare` shell, no permission, no session)
- status: built
- spec: `apps/hub/src/modules/sets/specs.ts` (`exampleSetSpec`)
- model: Opus 5 (ar-14)

## Purpose

The page a **client** opens when the studio sends them a set of examples. On S-12 someone ticks the projects they want to show ("review past stuff when building a portfolio, or sets of related examples to show specific clients", Justin in #past-projects), clicks **Open example page**, and gets this: a quiet, printable selection where each project reads as itself — cover, name, year, type, tags, location, a client-facing sentence when the studio has written one, and a strip of design previews that open in place. It is Spanish by default because the studio's clients are Spanish-first, it prints to a PDF with one project per sheet, and it carries nothing the studio marked confidential.

## Layout (top to bottom)

1. Quiet brand header: `BrandMark` wordmark, the page name as a kicker (only when the link carries a set title, otherwise the `h1` below says it), and the controls on the right, hidden in print: an **ES | EN** `ToggleButton` pair, **Print / Save as PDF**, **Copy link**.
2. `h1`: the set title from `&t=`, else "Ejemplos de proyectos" / "Project examples".
3. Intro line and the project count.
4. One section per project, in the order of the link: cover on the left (`Thumb` 16:9 `lg` from `coverUrl`, else a mosaic of `FileIcon`s for `project.fileTypes`), then name, year · type · location, tag `Badge`s, the client-facing summary when there is one.
5. **Design previews** per project: up to 8 `Thumb` buttons (images first), each opening the preview `Drawer`; "More images of this project on request." under the strip. A project with no publishable render says so in one sentence instead of showing an empty row.
6. Preview `Drawer`: `DocumentViewer` (`controls={false}`) over the served page renders, paged when the file has more than one page.
7. Footer: studio line, `aluzinaa.com`, "prepared by the studio for this conversation".

## Data

Read only. `projects` (`name`, `year`, `type`, `tags`, `location`, `summary`, `coverUrl`, `fileTypes`, `archiveSlug`) through `useTable('projects')`; a project's files through `useProjectFiles(project)` — the project's lazy chunk `docs/archive/projects/<slug>/index.json` overlaid by stored `assets` rows (ar-19), so a tag saved on S-13 reaches this page too. The page writes nothing at all: there is no set row, no share token, no analytics.

## Logic

- **The set is stateless in the URL**: `p` is a comma list of project ids in the order they are shown, de-duplicated; `t` is an optional title; `lang` is `es` (default) or `en`; `print=1` prints once. Nothing is stored, so a link needs no row, no auth and survives a re-seed, and the client can forward it. An id that matches no row is skipped silently — a client never reads an error about the studio's data.
- **Spanish by default**: the page translates itself with its own `translator(lang)` over the module's string table instead of calling `setLang`, so opening a client link in a tab never rewrites the studio's own EN session. The toggle writes `lang` into the URL, which is the single source of truth. (The `Drawer`'s own close button still comes from the app-wide table — the one string on the page that follows the session's language.)
- **Summaries are filtered, not rewritten** (`clientSummary`): whole sentences only, dropping the crawler's provenance (folder name, file and folder counts, crawl date, "featured project with a full index") and every "inferred; confirm with the founder" note. When nothing client-facing is left the paragraph is omitted rather than half-filled — today that is the case for the archived projects, whose summaries are entirely provenance.
- **Previews**: `clientPreviews` keeps files that have a served thumbnail and are neither tagged `confidencial` nor redacted by the crawler, puts images before documents (a photograph reads as the work, a document page reads as paperwork) and caps the strip at 8. A confidential file is never rendered and its name is never printed.
- **Location and tags**: the location prints only when it is not the seed's placeholder ("Ubicación no publicada"); tags drop the archive vocabulary (`archive`, `dropbox`, a bare year) and the project type, which already has its own line.
- **`print=1`** calls `window.print()` exactly once, after the projects resolve and 1.2 s of settle for the thumbnails (verified: 1 call). That is what S-12's **Export PDF** opens, so the PDF is the browser's own and the studio needs no export service.
- **The preview Drawer is page state, not URL state**: a client's back button leaves the set instead of closing a half-open dialog. `sets.openPreview` resolves an asset id or a file title against the previews the mounted sections have reported.

## Actions (P-05)

| id | label | intent | permission | params |
| --- | --- | --- | --- | --- |
| `sets.print` | Print or save as PDF | print this set of examples or save it as a PDF | — | — |
| `sets.copyLink` | Copy the link | copy the link to this set of examples | — | — |
| `sets.setLang` | Switch language | read this page in {lang} | — | lang: enum:es\|en |
| `sets.openPreview` | Open a preview | open the design preview {asset} | — | asset: id |
| `sets.closePreview` | Close the preview | close the design preview | — | — |

All five register while the page is mounted and were run through the bus (`window.__aluzina.actions.run`): `sets.copyLink` -> the absolute link, `sets.setLang {lang:'en'}` -> `'en'` with the page in English, `sets.openPreview {asset:'<file title>'}` -> the file title with the Drawer open, `sets.closePreview` -> `'closed'`.

## Components

`BrandMark`, `Thumb`, `FileIcon`, `Badge`, `Button`, `ToggleButton`, `Skeleton`, `EmptyState`, `Drawer`, `DocumentViewer`. No hand-rolled UI; `sets.css` is tokens only.

## Real vs mock / placeholder

Everything on the page is real: the projects and their files come from the store and the archive chunks, the previews are served renders, the print path is the browser's own dialog, the link is copied through `design/clipboard`. No `Placeholder` on this page. Mock: the identity of the reader (there is none — the page is public) and the summaries, which are still the crawler's text and therefore mostly filtered out until the founder writes client-facing lines (ar-08).

## Responsive and input check (P-01, P-03)

Verified with Playwright against the production build at 360, 390, 768, 1280, 1920, 2560 and 3840: 3 sections, 3 covers, 24 previews, **0 px horizontal overflow and 0 console errors at every width**, no interactive element under 44 px. One column up to 768, cover + body from 768 (20 rem cover, 26 rem from 1280), `--scale` carries the type at 2560 / 3840 with the container widened to 92 rem. Focus order: ES, EN, Print, Copy link, then per project the preview buttons in DOM order, then the footer link; the `Drawer` traps focus and Escape closes it (verified). Nothing hover-only, nothing drag-only. Light and dark come from the tokens (no literal colour outside the print block, which is deliberately `#000` on `#fff`).

Print (`emulateMedia({ media: 'print' })` at 1280): controls `display: none`, page `#fff` / `#000`, `break-before: page` on every project after the first, cover capped at 16 rem next to the facts, previews as a 4-column grid.
